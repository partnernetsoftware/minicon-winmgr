# 0.1.6 版本计划 — 设置日常可用与反馈闭环

> 起草：2026-10-15 · 基线：0.1.5 / `2f1a470`。
> 状态：W1–W5 已实现；本地质量与桌面验收完成，环境缺项如下；W6 交付与发布入口见 §8。
> 需求唯一入口：[PRD 6.1.1](prd_6_1_1.md)。本计划负责顺序、交付与验收，不复制需求。

## 1. 版本目标与边界

用户能通过鼠标或键盘修改设置，辨认当前生效值、来源及重启要求；保存失败有明确反馈并可重试。关闭任务栏后仍能打开设置；预览从关闭启动也能热开启。高 DPI、小工作区下所有操作可达。

本版不增加开始菜单按钮、主题编辑、热键重绑定、电源/IME 状态、通知中心或文件桌面。任务栏大拆分、全局可访问性、全桌面混合 DPI、小时级长跑与预览采样架构保留在 [后续清单](prd_5_1.md)，不沿用旧 0.2.0 草案的交付承诺。

## 2. 基线事实与设计决定

| 代码事实（静态核对） | 本版决定 | 需求 |
|---|---|---|
| `settings_ui` 自绘行主要靠鼠标，键盘只有 Esc | 使用原生控件、焦点顺序与可滚动内容区 | S1/S2 |
| 固定 460×720 客户区，主屏居中，无设置 DPI 分支 | 触发屏工作区布局、DPI 测量、固定反馈页脚 | S2 |
| `config::update` 先改内存，`persist` 无结果，同步文件 IO | 明确状态模型；独立有界串行保存，返回带代号的结果 | S3/S4 |
| 读取失败当空文件，备份失败仍继续直写目标 | 读失败停止、备份成功后临时文件替换，失败可重试 | S4 |
| `show_taskbar` 启动决定创建，UI 却用新偏好禁用相关项 | 区分运行状态与下次启动偏好，保留重启生效 | S3 |
| 环境变量加载时覆盖，UI 仍能改内存 | 展示有效来源，环境控制项只读 | S3 |
| `hover_preview::install` 禁用时提前返回，开关只请求 refresh | UI 线程幂等初始化，关闭取消计时/释放位图 | S5 |
| 设置入口依赖任务栏，二次实例直接拒绝 | `--settings` 呼出已有实例；无实例时启动并显示 | S1 |

## 3. 实施切片与依赖

顺序：W1 → W2 → W3 → W4 → W5 → W6。每片要求可构建、可验证；不按日历预估冒充承诺。

| 切片 | 交付物与主要模块 | 完成门槛 | 状态 |
|---|---|---|---|

| W2 保存链路 | `config` 与窗口装配：独立串行 worker、失败保真、备份/替换、重试及退出行为 | 隔离临时目录的真实文件测试与故障注入；慢 IO 不阻塞输入 | ✅ |
| W3 设置界面 | `settings_ui`：原生控件、键盘、焦点、滚动、反馈、来源与禁用原因 | 键盘完整修改/重试/关闭路径；桌面管理确认未退化 | ✅ |
| W4 DPI 与入口 | `settings_ui`、`main`、`single_instance`、`window`：工作区布局、DPI；`--settings` 请求路由 | 小屏与移屏、已有/无实例、启动就绪竞态、无任务栏入口 | ✅ |

| W6 集成验收 | 当前 PRD/README 状态、桌面证据、版本与发布说明 | 下表全部有结果，未覆盖环境明确登记 | ✅ 本地完成；CI/公开产物见 §8 |

仅为本版职责提取小模块；不把全仓 `pub` 收窄或任务栏大重构夹入切片。IO worker 不持 `bars/tasks` 锁，不调用 UI。任务栏更新仍经 hub，由消息线程应用。

交互延迟目标：普通设置和焦点反馈 ≤100ms，2s 慢保存不阻断消息循环；记录测量方法和分位数，不把目标写成已达成。保存成功必须对应当前请求已落盘；异步旧结果不能清除较新的未保存状态。

物理混合 DPI、热插拔与屏幕阅读器如无相应环境，必须登记“未覆盖”及影响，不以单测或截图模拟替代。若验收门槛需要调整，先更新需求与本矩阵，不能把缺项标成通过。

## 5. 风险与收敛规则

- 原生控件采用系统配色可能与任务栏深色不同：接受这一取舍，以可读、焦点与高对比度为先，不为换肤再建自绘控件系统。
- 保存是本版主要工程风险：先 W1/W2 固定状态和故障语义，再接 UI；不得只给当前 `persist()` 补一个成功提示。
- 文件替换的原子性、备份与失败路径需按实际 Windows 行为测试；未检测的任意外部编辑竞态不宣称已彻底解决。
- 设置入口与单实例握手必须限定同一用户会话及固定动作，不扩成远程命令通道。
- 预览仅修生命周期；若基线慢目标阻塞影响设置验收，记录复现并重新评估 FUT-07，不用异步保存掩盖截图阻塞。

上述缺项作为本版明确的环境与交互覆盖限制随发布披露；S1–S5 的代码交付不等同于完整环境认证。后续应优先补实际混合 DPI、屏幕阅读器、高对比度及可见预览流程。

## 8. 发布核验

- 本地：`cargo fmt --all --check`；`cargo clippy --all-targets -- -D warnings`；`cargo test --all --quiet`（250）；`cargo build --release --target-dir target/release-0.1.6`。
- 桌面：`python scripts/settings_probe.py`；详细成功记录在 JSON。随后输入桌面出现访问拒绝，未把不能注入输入时的失败当成产品结果，补充 UI Automation/资源检查不依赖输入注入。
- CI：[最终 main 的检查](https://github.com/partnernetsoftware/minicon-winmgr/actions/workflows/ci.yml)。
- 公开版本：[v0.1.6](https://github.com/partnernetsoftware/minicon-winmgr/releases/tag/v0.1.6)；发布后核验非 draft、非 prerelease、tag 指向最终代码且 Windows exe 可下载。

补充性能采样：正常配置下 100 次同步隐藏/显示，中位 75.8ms、P95 108.8ms、最大 176.7ms（不含磁盘完成）；不能据此宣称全部呼出均 ≤100ms。2s 慢保存期间原生 Tab/Esc 的输入响应测试独立通过。
