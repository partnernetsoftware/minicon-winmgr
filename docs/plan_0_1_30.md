# 0.1.30 计划：任务栏置顶自愈与重复启动反馈

状态：计划（2026-11-07）。版本号仍为 0.1.29，未开发。承接 0.1.29 的公开发布，背景见 [plan_0_1_29.md](plan_0_1_29.md) 与 [validation_0_1_29.md](validation_0_1_29.md)。

## 1. 用户问题

- **任务栏消失（已在真机出现）**：外壳进程仍在运行、任务栏窗口仍存在且可见，但被桌面窗口盖住，屏幕底部看不到任务栏。手动把任务栏置顶后恢复。
- **重复启动无反应**：对同一个 exe 再次启动（例如从任务管理器运行），新进程静默退出，不弹窗、不打日志，用户以为外壳挂了。

## 2. 已确认的事实

- 2026-11-07 排查时，任务栏窗口在 z 序上低于桌面窗口，且不带 `WS_EX_TOPMOST`。
- 桌面窗口每次显示都由 `desktop_surface.rs` 的 `fit_and_show` 用 `HWND_BOTTOM` 摆放（启动、`WM_DISPLAYCHANGE`、外观刷新都会调用）。
- 代码中把任务栏放到底层的只有全屏让位分支（`taskbar.rs`，`bar_insert_after` 与 `update_fullscreen_yield`）；让位结束时以 `HWND_TOPMOST` 恢复，但该 `SetWindowPos` 的返回值被忽略。
- 同一构建重复启动：`instance_switch::acquire` 比较哈希相同后返回 `Ok(None)`，`run_companion` 直接返回，不产生任何日志或界面。

## 3. 未确认的部分

- 任务栏失去置顶的确切时刻和调用方。日志中全屏让位的最后一次记录是 08:45:16 UTC（`yielded=false`），之后没有 z 序相关记录，因此需要增加观测，而不是凭推测修复。

## 5. 不在本版

- 0.1.28 起的“显示桌面”在左右任务栏时把最小化窗口标题条放到屏幕底部（见 [readme](../readme.zh.md) 的已知问题）。它与本版的置顶问题无关，本版不修。

## 6. 停止条件与风险

- 若 A 的观测在复现中没有出现 z 序变化，B 与 C 仍然作为防护实施，但验收记录中写明“根因未确认”。
- D 只改变启动反馈，不改变已运行实例的行为。
- 发布需要签名运行，按 0.1.29 的流程执行；签名运行本身需要 owner 明确同意。
