# 工具产品边界与集成

> 稳定索引：7.1。上位：[PRD](prd.md)。更新：2026-10-20。
> 状态：用户已授权顺序开发 .15/.16/.17 并分别公开发布；.15 已交付，.16 核心、原生管理界面、外壳集成和双产物交付已实现，准确候选验收中，尚未发布；Sysmgr 尚未实施。

## 1. 产品分工

三项产品近期在 Windows 落地，长期预留 macOS/Linux 适配及 computer-use / mind-use 底层服务能力，详见[跨平台原则](prd_7_2.md)。独立运行、统一入口、共享基础代码；暂不建立插件系统。

| 产品 | 核心职责 | 边界 |
|---|---|---|
| minicon-winmgr | 桌面外壳、窗口与应用入口 | 保持轻量、普通权限；提供工具入口，不承载整机采样与特权管理 |
| minicon-tskmgr | 应用、进程和网络管理 | 回答“哪个应用在运行、占资源、建立连接，如何处理”；进程资源用量用于定位责任对象 |
| minicon-sysmgr | 整机内存、磁盘、硬件等监控与管理 | 回答“整机资源与设备是否健康，哪里有瓶颈”；管理动作按具体需求立项，不因名称自动包含所有系统修改 |

网络按对象划分：进程连接、端点、可归属的进程流量及相关管理归 Tskmgr；网卡、链路状态与整机接口吞吐归 Sysmgr。两个产品可互相跳转，采样能力可共享，但不重复拥有同一项管理动作。Tskmgr 中的进程内存/磁盘 IO 与 Sysmgr 的整机内存/磁盘状态互补。

Sysmgr 不再定位为包办所有工具的“大管家”。Winmgr 只是统一入口之一；没有安装或运行 Winmgr 时，两个工具仍能独立使用。

## 2. 运行与代码组织

- 工具运行在独立进程中，关闭或崩溃不能拖垮 Winmgr；启动工具不创建第二条任务栏、不接管外壳、不修改登录 Shell。
- 初期优先同仓维护多个可执行目标，共享有实际复用价值的主题、控件、只读采样与错误处理。独立进程不要求独立仓库、安装器或重复实现。
- 实施前确定目标名、产物布局、工具定位及更新契约；不得假定当前单 exe 更新器已支持多个 exe。共享库不为未来抽象而一次性重构现有外壳。
- Winmgr 入口只启动已明确定位的工具，不从任意 PATH 或用户配置中猜测管理员目标。缺失、不兼容或启动失败时显示可操作反馈，保留 Windows 自带任务管理器入口。
- 普通入口可传入窗口对应进程的定位信息；工具重新核实进程身份，窗口和进程是一对多关系，不能把窗口按钮当成完整进程枚举。
- 查询、采样与管理动作和 GUI 分离，Windows 特有类型集中于平台适配边界；未来结构化调用复用同一能力，不依赖模拟点击 GUI。当前不增加自动化服务端。
- 初期协议限于启动、定位和结果反馈；不提供任意命令执行的通用特权接口。不建设进程内 DLL 插件加载、插件市场或稳定插件 ABI。

## 3. Tskmgr 双入口与权限

| 入口 | 默认范围 | 权限与行为 |
|---|---|---|
| 我的任务 | 原交互用户的进程，默认突出当前会话；其他会话另分组 | 普通权限打开，搜索/排序/查看与允许的管理操作可用 |
| 所有用户与系统任务 | 按用户、会话分组的进程及可查询系统任务 | 用户主动点击后发起 UAC，成功后打开独立管理员窗口 |

- 所属用户、会话与权限状态分别显示。“我的进程”不等于可无条件操作：自己已提权的进程也可能要求管理员入口；受限项显示原因和按需升级入口。
- Winmgr 始终普通权限运行。管理员 Tskmgr 不走外壳的“提权启动后降权重开”分支；进程角色在任何外壳初始化和单实例转发之前分流。
- UAC 取消不改变原视图、筛选或选中项，不报告操作成功；关闭管理员窗口即结束该窗口的授权生命周期，不安装常驻特权服务。
- 标准用户提供另一管理员账户凭据时，原用户与提权账户可能不同；“我的任务”仍以核实的原交互用户为准，不能误切为凭据账户。普通/管理员实例及不同会话不能互相错误转发。
- 权限按实际访问结果判断；管理员入口不承诺任意操作受保护进程。身份未知不猜测归属，部分信息不可读不隐藏整行、不伪造零值。
- 动作执行前复核 PID 与创建时间等身份，处理进程退出和 PID 复用。正常关闭窗口与强制结束进程明确区分；批量或进程树结束另行定义范围与部分失败反馈。

## 4. 分阶段能力

### Tskmgr 首期：我的任务

- 进程列表与可展开的应用/进程关系；搜索、稳定排序，CPU、内存、PID、路径及会话信息按可得性呈现。
- 从 Winmgr 窗口定位对应进程；切换到窗口、正常关闭、明确确认的强制结束。
- 打开文件位置、复制路径/命令行；命令行可能包含私人信息，不自动写入公开报告。
- 基础网络视图：可归属到当前用户进程的 TCP/UDP 端点、TCP 状态，区分本地/远端；UDP 不伪造远端与连接状态。不可得的数据明确标识。
- 进程网络速率不是端点列表的自然附属能力；需另验采集来源、权限、开销与归属准确性，未完成前不承诺实时流量。

### Tskmgr 后续：管理员管理与网络增强

- 双入口、真实授权/取消、跨账户凭据及会话边界；管理员窗口可查看和处理允许访问的其他用户/系统进程。
- 网络速率与历史按单独可行性结果收口；“结束进程”“关闭连接”“阻断联网”是不同动作，不能互相冒充。
- 防火墙规则、连接干预不纳入首期，实施前定义规则归属、授权、撤销和失败语义。结束进程树、服务控制、优先级修改也不默认随管理员入口交付。

### Sysmgr：整机监控先行

- 首期建议只读：物理/提交内存及趋势、CPU 与硬件信息、卷容量与磁盘 IO、设备/网卡状态及整机接口吞吐。
- 温度、风扇、SMART、GPU 等先确认 Windows 支持、厂商差异与权限；来源不支持时显示不可用，不承诺所有硬件可读，也不直接引入内核驱动。
- 管理能力后续按用户问题逐项定义，例如定位容量占用、打开设备相关系统入口。清理文件、修改设备/存储设置等需独立规格和验收，不能从“监控”自然扩展为自动处置。
- 内存管理不以强制清空工作集或展示“释放了多少内存”作为默认功能；先区分工作集、提交、缓存与实际内存压力。

## 5. 完成与验收原则

工具能独立启动，且实际入口、窗口定位、权限隔离、重复打开及正常退出均有证据。采样异步、有界，隐藏/关闭后停止不必要工作；记录空闲及大量进程/连接场景的 CPU、内存和句柄，不给外壳增加常驻采样负担。

进程退出/复用、访问拒绝、窗口挂起、网络连接快速变化均需覆盖；数值显示来源、采样周期与不可用原因。危险动作测试只针对明确拥有的测试进程，不触碰真实用户任务。

发布前确认各 exe 的源码、版本与摘要关系，并验证缺失工具、更新失败及版本不匹配。准确 CI 候选原样发布的规则继续适用；工具自身版本不预设与 Winmgr 永久同步。
