# 0.1.18 计划：可靠的工具获取与离线识别

状态：修复实现及本地定向验收完成，尚未公开；CI 候选及公开交付待执行。前置 [0.1.17](plan_0_1_17.md) 已公开，不替换其附件或标签。需求依据：[工具 PRD](prd_7_1.md)。

## 1. 用户问题与目标

.17 的工具已手动下载到 Winmgr 所在目录，却因没有 SHA256SUMS.txt 被忽略；不同账户的网络或代理条件不同，重新下载也可能失败。当前已复核一例：两份官方 .17 文件摘要正确，补齐同版校验表后实际 My tasks 能直接打开同目录工具。另一处下载失败尚缺具体错误，不把账户代理差异当作已证实根因。

.18 的目标是：**两份同版官方 exe 放在同一目录，即使断网也能通过校验并打开；不能打开时明确说明卡在哪一步。** 保持按需下载、普通权限和独立工具边界。

## 2. 任务树与依赖

```text
0.1.18 工具获取可靠性
├── A 官方产物绑定
│   ├── [x] 先构建 Tskmgr，计算摘要，再构建内置该摘要的 Winmgr
│   ├── [x] 打包时核对内置构建摘要与实际工具一致
│   └── [x] 保留旧构建/开发构建的校验表回退契约
├── B 本地识别（依赖 A）
│   ├── [x] 同目录优先、用户缓存回退；内置摘要验证不依赖校验表或外网
│   ├── [x] 篡改、错误版本和读取失败明确拒绝；不搜索任意 PATH
│   └── [x] 区分文件缺失与本地文件校验失败，展示离线修复步骤
├── C 下载失败反馈（本地无有效工具时）
│   ├── [x] 区分获取校验表、传输工具、保存及内容校验阶段
│   ├── [x] 明确使用系统/当前用户代理，保留实际错误供定位
│   └── [x] 已有本地文件时优先校验利用，避免不必要的整份下载
└── D 定向验收与交付
    ├── [x] 生产方式构建的两份 exe：无校验表、空缓存，实际入口打开
    ├── [x] 错误摘要拒绝、有效缓存回退、失败重试及打包绑定检查
```

A → B → 本地入口冒烟是主路径；B 没有可用工具才进入 C。网络失败不能让已通过本地校验的工具变得不可用。

## 3. 实施约束

官方构建先生成工具，用该工具真实 SHA-256 编译 Winmgr；现有 BUILDINFO 与校验表继续记录两份文件，打包拒绝缺失或错误的绑定输入。不采用运行未知 exe 自报版本的方式建立信任，不因名称相同就跳过内容校验。

开发构建没有内置摘要时继续使用同版校验表，并如实说明要求；管理员入口复用相同的已验证路径及现有文件锁和授权流程。下载仍使用 Windows 自动代理配置，不修改用户代理、不复制其他账户凭据、不关闭 TLS 验证，也不预设 HTTP_PROXY 等环境变量等同于系统代理。

现有本地文件如能匹配从本版公开发布取得的校验表，应利用该文件而不是再下载完整工具；失败不覆盖原文件。校验表获取仍可能依赖网络，故不能替代官方内置摘要的离线主路径。

## 4. 测试分层与停止条件

| 风险 | 最小验证 | 复用 |
|---|---|---|
| 绑定错误或无校验表打不开 | 构建/打包定向测试；生产方式双 exe 的一次实际离线入口 | .17 账户与 UAC 语义 |
| 误信任篡改文件或丢失回退 | 本地与缓存的摘要正反例；原文件保持 | 未改的进程管理动作 |
| 下载失败仍无法定位 | 阶段化错误路径、已有中断/错误内容/重试组件 | WinHTTP 未改的取消和 TLS 契约 |
| 发布错配 | 准确候选晋升、两个附件及实际公开更新 | Winmgr 全套历史 UI |

相关静态检查与定向验证通过即停；权限实现未改则不重复 UAC 或跨账户环境矩阵。真实网络/代理故障若缺环境或错误码，记录限制，不制造“代理问题已修复”的结论。发布步骤完成后才能标记公开交付。

## 5. 后续产品路径

树式任务管理 → 稳定任务对象 → 人工笔记与状态 → agent 同契约读写 → 有证据的异常辅助，沿用 [PRD §7](prd_7_1.md#7-下一阶段树式任务管理与持续分析)。本次先解除工具无法使用的阻碍，不把尚未设计完成的协作笔记、异常规则或常驻 agent 服务捆绑进修复版；后续具体版本随任务拆分确定。

实现与本地验证见[验收记录](validation_0_1_18.md)。未覆盖的另一台 Windows 网络故障继续等待具体错误与环境证据；不影响已验证的双 exe 本地路径。
