# 0.1.18 计划：树式任务管理与协作分析

状态：已合 main 并公开交付（2026-10-21）。准确候选、公开附件、真实 .17 → .18 更新及同版工具下载通过。前置 [0.1.17](archive/plan_0_1_17.md) 已公开，不替换其附件或标签。需求依据：[工具 PRD](prd_7_1.md)。

## 1. 用户问题与目标

用户再次明确：进程平铺不便管理，要树式组织，并允许人和 agent 持续补充分析笔记、主动标识异常。**.18 的主线是可持续管理任务，而不是只修工具下载。** 下载与离线识别修复保留为本版基础能力。

.17 的工具已手动下载到 Winmgr 所在目录，却因没有 SHA256SUMS.txt 被忽略；不同账户的网络或代理条件不同，重新下载也可能失败。当前已复核一例：两份官方 .17 文件摘要正确，补齐同版校验表后实际 My tasks 能直接打开同目录工具。另一处下载失败尚缺具体错误，不把账户代理差异当作已证实根因。

.18 的目标是：从树中定位任务，持续积累人工与 agent 分析，并在主视图追踪异常和处理状态；同时让两份同版官方 exe 放在同一目录时，即使断网也能校验并打开，失败时明确说明阶段。保持按需下载、普通权限和独立工具边界。

```text
├── [x] 本地持续笔记：追加历史、作者、时间、依据和版本冲突保护
├── [x] 人工原生笔记编辑及关注/异常/已处理状态
├── [x] agent 结构化读取与追加，复用同一存储及并发校验
├── [x] 异常/关注标识在主视图可见，可筛选，保留依据和处理历史
└── [x] 实际路径：树中定位 → 人工笔记 → agent 补充 → 状态更新 → 重启保留
```

## 3. 实施约束

官方构建先生成工具，用该工具真实 SHA-256 编译 Winmgr；现有 BUILDINFO 与校验表继续记录两份文件，打包拒绝缺失或错误的绑定输入。不采用运行未知 exe 自报版本的方式建立信任，不因名称相同就跳过内容校验。

开发构建没有内置摘要时继续使用同版校验表，并如实说明要求；管理员入口复用相同的已验证路径及现有文件锁和授权流程。下载仍使用 Windows 自动代理配置，不修改用户代理、不复制其他账户凭据、不关闭 TLS 验证，也不预设 HTTP_PROXY 等环境变量等同于系统代理。

现有本地文件如能匹配从本版公开发布取得的校验表，应利用该文件而不是再下载完整工具；失败不覆盖原文件。校验表获取仍可能依赖网络，故不能替代官方内置摘要的离线主路径。

## 4. 测试分层与停止条件

| 风险 | 最小验证 | 复用 |
|---|---|---|
| 树过滤或状态跨 PID/账户串用 | 搜索祖先、运行/应用状态优先级与 PID 复用定向单元 | 未改的终止权限规则 |
| 笔记被覆盖、损坏或重启丢失 | 锁/持久化/损坏组件；人工→agent→冲突保留草稿→复核→重启的实际路径 | 不重复桌面外壳全回归 |
| 绑定错误或无校验表打不开 | 构建/打包定向测试；生产方式双 exe 的一次实际离线入口 | .17 账户与 UAC 语义 |
| 误信任篡改文件或丢失回退 | 本地与缓存的摘要正反例；原文件保持 | 未改的进程管理动作 |
| 下载失败仍无法定位 | 阶段化错误路径、已有中断/错误内容/重试组件 | WinHTTP 未改的取消和 TLS 契约 |
| 发布错配 | 准确候选晋升、两个附件及实际公开更新 | Winmgr 全套历史 UI |

相关静态检查与定向验证通过即停；权限实现未改则不重复 UAC 或跨账户环境矩阵。真实网络/代理故障若缺环境或错误码，记录限制，不制造“代理问题已修复”的结论。发布步骤完成后才能标记公开交付。

## 5. 本版管理能力依赖与边界

树式视图与稳定任务对象 → 本地追加存储与并发保护 → 人工编辑和状态 → agent 同契约读写 → 主视图标识与筛选。以上为本版实现范围，沿用 [PRD §7](prd_7_1.md#7-下一阶段树式任务管理与持续分析)。

默认笔记绑定本次运行；路径可得时可显式切换整个应用范围跨重启积累，两者历史分开。用法及 agent 请求契约见[任务分析](task_analysis.md)。人与 agent 的来源分别标注，推测、依据和状态不冒充操作权限。异常标识由人或 agent 主动设置，不能自动结束任务或提权；本版不内置模型服务，不把未经验证的阈值叫作恶意检测。

实现和本地验证见[验收记录](validation_0_1_18.md)。未覆盖的另一台 Windows 网络故障继续等待具体错误与环境证据；不影响已验证的双 exe 本地路径。
