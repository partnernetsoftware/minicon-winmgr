# 0.1.10：低开销、可解释、经得起长时间运行

状态：边细化设计边开发，尚未宣称内存优化或长跑验收完成。基线为公开 0.1.9。需求归属：[可靠性底座](prd_2_1.md)、[后续清单 FUT-02 / FUT-07 / FUT-08](prd_5_1.md)。

目标是日常使用后占用能趋于稳定、异常应用不会拖死外壳、失败后仍能继续使用。保持默认英文、紧凑暖色设置、按需加载与普通用户权限；不添加常驻诊断面板、默认遥测或启动联网。

## 一、先把内存测准

| 指标 | 用途与边界 |
|---|---|
| Private Bytes / PrivateUsage | 进程私有提交量，观察长期分配走势；不等于物理驻留量 |
| Working Set | 当前驻留物理页，包含共享部分，受系统调度影响 |
| Private Working Set | 单独通过适用的系统计数器采集，不能拿 PrivateUsage 冒充；不可用时明确留空 |
| 句柄、GDI/USER 对象、线程数 | 识别 native 资源与 worker 未退出；记录当前值、峰值、阶段差值 |
| 缓存条目、估算字节、待处理任务数 | 定位增长来自哪个模块；区分常驻缓存、短时峰值和不可达资源 |

新增独立外部采样工具，默认每 5 秒记录数值和场景代号；仅绑定指定测试实例及其创建时间，进程退出或身份变化即停止，不跟随复用 PID。默认不采集窗口标题、应用命令、账户、工作目录或文档内容。原始数据与趋势图留在本地；公开文件由字段白名单生成，人工审阅后发布。

同一机器、同一优化构建配置、同一场景规模至少重复三次。记录版本、二进制摘要、Windows 版本、显示配置、功能开关、采样间隔与观察时长。诊断工具开销单独记录，不计入 winmgr 的“优化成果”。

场景分为：冷启动与空闲、首次打开设置/Run、300 次窗口开关、200 次中英/主题/位置切换、可控窗口及图标 churn、预览开关、更新检查/下载失败与重试、返回空闲。不同场景使用新进程或明确标记共享预热，分别保留 5 分钟预热、操作期及 10 分钟静置回收数据。

先完成 30 分钟定位，再跑 2 小时稳定性，发布候选跑至少 8 小时。暂不能完成的物理环境单列，不用短测替代。统计首尾窗口中位数、P95、峰值及 MiB/小时增长趋势，保留原始采样依据；不靠 EmptyWorkingSet 或定时强制修剪制造低数字。

## 二、按资源所有权修复增长

| 审计对象 | 拟实施约束 | 验证方式 |
|---|---|---|
| 图标、字体、位图、DC | 每个 native 对象明确 owner；区分 borrowed/owned，选入 DC 的对象先恢复再释放；错误与窗口销毁路径同样释放 | churn 后对象计数回到稳定带；故障注入不持续增长 |
| 图标/路径/预览缓存 | 记录命中与字节；定义条目数和字节双上限、淘汰与失效策略；窗口消失及时移除；上限按基线确定并写入实现 | 重复相同输入趋稳，大量不同输入仍有界；无 stale HWND/PID 复用错误 |
| Run 建议与后台任务 | 保留最新查询、合并重复任务，限制队列；结果携带 generation，关闭或新输入后丢弃过期结果 | 快速输入、慢磁盘、反复开关不积压，不用每次输入新建线程 |
| 设置/主题/任务栏 | 检查窗口复用、DPI 字体替换、每屏对象与定时器撤销；避免锁内 I/O 和调用其他窗口 | 连续切换无线性 GDI/USER/句柄增长，工作区恢复一致 |
| 更新下载与助手 | 响应、计划文件在读取前限制长度；采用有界缓冲/流式写入并校验；完成后释放网络句柄和线程 | 超长/截断/慢响应、重试、关闭窗口、交接失败；旧版仍能运行 |

基线出来前不批量重构。每个优化必须有“增长原因 → 所有权/上限修复 → 同场景前后对照”，不能仅以换分配器、缩容所有容器或减少功能证明有效。

## 三、稳健性与卡顿隔离

0.1.9 的 `hover_preview` 在界面路径同步调用 PrintWindow，曾是首要响应性风险。该 API 可能阻塞，移到普通线程并设置 UI 等待超时也不能保证底层调用结束。0.1.10 开发已选择 DWM 合成关系，取消同步截图；不得在每次超时后遗留一个新线程。无法取得预览时显示简洁占位并保持任务切换可用，预览仍默认关闭。

外部窗口消息、文件/网络访问均需时间和大小边界。UI 不等待未知应用响应，不在持有任务列表/缓存锁时执行外部调用。退出标记取消，异步结果不再触碰销毁窗口；资源释放不能依赖一次成功回调。

更新流程补充故障矩阵：离线、限流、慢响应、连接断开、磁盘不足、不可写目录、重复点击、退出时仍下载、助手/候选进程异常退出、回执超时。只操作本实例创建的目录与子进程；不终止其他会话，不自动申请 UAC。更新备份清理单独设计，只在确认当前版本可用后提供显式操作，不扫描和删除任意相似目录。

配置写入故障保留旧文件及重试入口。日志按大小/数量轮转，诊断有界，默认不记录用户输入和路径。断言、panic 与 unsafe/FFI 边界重点检查；Rust 的内存安全不能替代 Win32 资源生命周期验证。

## 四、UI/UX：诊断保持可选

主设置维持现有三组布局。高级“配置与关于”可增加折叠的“诊断 / Diagnostics”入口：显示简短状态、明确测量起止时间，以及“开始记录 / 停止 / 导出已脱敏摘要”。用户未启动诊断时不创建采样定时器或线程。此入口是 P1，P0 优先交付外部工具及资源修复。

导出前展示字段范围并允许取消；默认只导出版本、指标、场景和结果，不展示内部环境变量名。失败反馈使用可理解文案，技术详情按需展开；中英文、明暗主题、键盘和紧凑布局同步验收。README 只展示通过实测的结果与条件，不提前写“零泄漏”或固定内存承诺。

## 五、交付顺序与验收门槛

1. **P0 证据边界**：原始报告退出版本库，脚本改为本地输出，CI 拒绝原始报告及已知工作站路径；公开摘要和截图人工审阅。本轮已落实，历史副本仍需独立处理。
2. **P0 基线**：可复现外部采样与场景驱动，生成本地曲线和不含路径的公开摘要；在基线上冻结每场景内存、对象计数及响应预算。
3. **P0 修复**：优先处理已复现的持续增长、无限队列和界面阻塞；逐项记录前后对照。预览调用隔离必须验证无法返回的被测窗口。
4. **P1 诊断交互与长跑**：可选界面、2 小时/8 小时观察、故障矩阵，最后完整 release 验收。

开发增加独立 `memory`、`resources`、`fault`、`soak` 层；采样长度和场景可选，`soak` 必须显式给定时长。发布入口统一调度全部层及长跑前提，不能把没有执行的长跑标成通过。现有单元/设置/Run/更新等层继续可单独运行。

暂定回归门槛：相同场景对照基线若私有提交中位数增加同时超过 10% 和 2 MiB，或 GDI/USER/句柄在静置后随循环次数持续增加，阻止发布并归因。预热后重复负载仍持续线性增长、不可恢复卡死、丢配置或破坏工作区均阻止发布。统计阈值只是报警线，不能用于容忍已确认的泄漏。确有必要的有限缓存成本需写明上限和收益，经重新基线验证。

交付物：采样及场景工具、[资源所有权审计表](resources_0_1_10.md)、针对性修复、优化前后曲线、公开验收摘要、未覆盖环境清单；完整发布前不改成“已完成”。

### 日志队列归因

依赖的默认非阻塞队列为 128,000 槽位，当前改为 512，饱和丢弃日志而不把磁盘背压传到界面。受控 debug 实验每种容量独立启动三次进程：队列创建前后私有提交增量中位数分别 4,141,056 字节与 32,768 字节，差值 4,108,288 字节（约 3.92 MiB）。只归因于这个初始化路径，不当作整个应用的新基线；优化构建重复实验获得相同差值；整个应用的完整场景仍需对照。阻塞写入器测试验证饱和时调用者不阻塞，并在结束时释放测试 worker。

快捷启动补充：限制原始文件 1 MiB，解析只保留 8 项；读取损坏/超长文件时禁止覆盖。持久化改为同目录唯一临时文件和替换，检查外部修改，失败保留原文件。验证包含替换前故障、非法编码、外部修改及真实文件占用；不据此承诺断电或所有文件系统故障都能恢复。

第一轮公开证据见[开发验收摘要](validation_0_1_10.md)，不代表 2 小时/8 小时或完整 release 已通过。

### 日志的第二轮约束（开发）

每条格式化日志最多 16 KiB（超长内容标记截断），在进入 512 槽队列前生效；文件和 stderr 共用该格式边界。磁盘改用固定的新文件组：一个 current 和三个备份，每个最多 8 MiB，总预算 32 MiB（不含既有历史日志）。只轮换本文件组，不扫描/清理旧 daily 日志或其他文件。

写盘和轮换均在现有日志 worker，短时间独占本文件组的锁文件以协调同目录的多进程日志。锁被占用、目录不可写、轮换失败时丢弃该条日志，不阻塞消息线程或阻止启动；不声称日志永不丢失。日志目录创建也移到 worker。已通过真实格式化事件的 UTF-8 截断/后续事件验证，以及文件系统层重启续写、轮换预算、文件占用、并发写入和目录路径拒绝验证；长期高频场景仍待采样。

### 用户级偏好文件

默认保存 `~/winmgr.cnf`（Windows `%USERPROFILE%\winmgr.cnf`）；不带参数启动恢复语言、主题、位置、侧栏宽度及设置面板的其他偏好。旧 exe 旁设置仅在新文件缺失时作为迁移来源，首次成功保存连同注释和未改动项一起迁入；新文件存在后不再受旧文件影响。显式 `MINICON_SETTINGS` 保持隔离，环境覆盖优先级保持不变。异步、备份、原子替换、外部修改检查及失败重试沿用；读取和写出均限制 1 MiB。已用两个独立进程验证实际设置入口异步保存后，新进程自动加载全部九项偏好，不指定设置文件路径。侧栏实机验收已改用隔离用户目录，但本轮重跑未通过，范围与失败记录见开发验收摘要；不以独立进程测试替代真实鼠标与工作区验收。

### 窗口图标查询从 UI 移出

原实现为每个窗口同步执行最多三次 50ms 的 WM_GETICON，且绘制借用窗口拥有的 HICON。现改为一个按需启动、进程内固定复用的 worker；UI 只读完成快照，冷启动先用既有文字/首字占位，完成消息只更新图标并重绘，不递归触发完整刷新。

每轮最多处理 256 个窗口，当前缓存和完成结果各自有数量上限；仅保留一个最新 pending 和一个 ready，请求 generation 过期后丢弃结果，通知消息也合并为最多一个未消费项。每次外部消息等待最多 12ms，一批消息等待共用 64ms 截止时间；该预算不等于包含 OS 调度与复制图像在内的硬实时承诺。超时不为同一窗口再试另两个消息，转类图标；读取失败保留同一身份目标已有的有效 owned 快照，没有快照才用文字占位。worker 使用独立队列，不调用 AttachThreadInput，UI 不再发送 WM_GETICON。

窗口图标用 CopyImage 复制为独立 32×32 图像，当前缓存、task item 和 paint 持有共享引用，最后引用 DestroyIcon；不销毁来源的 borrowed 图标。以 HWND/PID/thread 匹配当前目标，发布结果须匹配当前请求 generation，关闭后不会绘制失效的借用句柄。数量/尺寸上限不冒充整个 Windows 图形资源字节数；新增一个 worker 和拥有图像的成本须纳入全应用对照。

隐藏窗口专项已覆盖正常响应、同一源线程停滞、1000 次请求合并、通知合并、类图标回退、源窗口关闭后快照有效与最后引用释放。实验只操作本测试创建的隐藏窗口，不发送鼠标输入，不替换正常外壳。更多实际应用、整个任务栏可视表现和长跑仍需后续验证。

API 依据：[SendMessageTimeoutW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendmessagetimeoutw)（同队列直接调用会忽略 timeout，故不在 UI 线程做查询）、[CopyImage](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-copyimage)（指定尺寸，未使用返回原对象的标记）。

### 更新下载与校验的内存峰值

下载 exe 改为 WinHTTP 16 KiB 块直接写入本次唯一暂存文件，不再构造整份响应 Vec。小型 API/校验和文本继续保留原有 512 KiB / 64 KiB 上限。exe 仍限 64 MiB；已知 Content-Length 超限时在消费前拒绝，未知长度按实际字节计数，截断或读取后整体预算超限不能进入 Ready。WinHTTP 原生操作仍使用既有分阶段超时，检查点不等于能硬打断每个原生调用；更完整慢网络故障矩阵待补。

`update_stream` 使用固定 16 KiB 缓冲与增量 CNG SHA-256；PE 的 DOS/目标头通过 seek + 小数组验证，之后流式哈希。准备阶段流式复制并哈希旧 exe 为 helper；重启前、等待退出后与恢复判断都流式复核，清单仍只读取 16 KiB + 一个探测字节。校验/下载/复制失败清理本次自建固定文件，当前安装不改写；无法清理时保留错误，不承诺所有文件系统故障都能删掉暂存。

新增独立 `update-memory` 层：32 MiB PE 形状测试文件，在独立进程对照旧的双整文件缓冲与实际流式 prepare 路径，每种模式三次，debug 和优化构建分别执行。它测准备阶段私有提交增量，预热 CNG，观察线程成本在两组保持一致；不含网络/TLS/实际外壳。结果见[开发验收](validation_0_1_10.md)，不替代全应用或长跑。

真实 update 层已验证下载后仍保留旧进程、重启前二次校验、保存失败禁止交接、两版本交接、文件占用恢复和回执失败回滚，共 15 项。测试版本从 Cargo 当前及上一补丁动态生成，旧 fixture 为当前代码回移，不冒充历史公开版。结束恢复原 live 二进制与环境，并以摘要检查恢复结果。源码版本仍暂保留基线，不据此宣称 0.1.10 已发布。

增量哈希依据：[BCryptCreateHash](https://learn.microsoft.com/en-us/windows/win32/api/bcrypt/nf-bcrypt-bcryptcreatehash)、[BCryptHashData](https://learn.microsoft.com/en-us/windows/win32/api/bcrypt/nf-bcrypt-bcrypthashdata)。hash 对象先销毁，再关闭算法 provider；错误路径同样释放。
