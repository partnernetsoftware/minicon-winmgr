# 0.1.10：低开销、可解释、经得起长时间运行

状态：边细化设计边开发，尚未宣称内存优化或长跑验收完成。基线为公开 0.1.9。需求归属：[可靠性底座](prd_2_1.md)、[后续清单 FUT-02 / FUT-07 / FUT-08](prd_5_1.md)。

目标是日常使用后占用能趋于稳定、异常应用不会拖死外壳、失败后仍能继续使用。保持默认英文、紧凑暖色设置、按需加载与普通用户权限；不添加常驻诊断面板、默认遥测或启动联网。

## 一、先把内存测准

| 指标 | 用途与边界 |
|---|---|
| Private Bytes / PrivateUsage | 进程私有提交量，观察长期分配走势；不等于物理驻留量 |
| Working Set | 当前驻留物理页，包含共享部分，受系统调度影响 |
| Private Working Set | 单独通过适用的系统计数器采集，不能拿 PrivateUsage 冒充；不可用时明确留空 |
| 句柄、GDI/USER 对象、线程数 | 识别 native 资源与 worker 未退出；记录当前值、峰值、阶段差值 |
| 缓存条目、估算字节、待处理任务数 | 定位增长来自哪个模块；区分常驻缓存、短时峰值和不可达资源 |

新增独立外部采样工具，默认每 5 秒记录数值和场景代号；仅绑定指定测试实例及其创建时间，进程退出或身份变化即停止，不跟随复用 PID。默认不采集窗口标题、应用命令、账户、工作目录或文档内容。原始数据与趋势图留在本地；公开文件由字段白名单生成，人工审阅后发布。

同一机器、同一优化构建配置、同一场景规模至少重复三次。记录版本、二进制摘要、Windows 版本、显示配置、功能开关、采样间隔与观察时长。诊断工具开销单独记录，不计入 winmgr 的“优化成果”。

场景分为：冷启动与空闲、首次打开设置/Run、300 次窗口开关、200 次中英/主题/位置切换、可控窗口及图标 churn、预览开关、更新检查/下载失败与重试、返回空闲。不同场景使用新进程或明确标记共享预热，分别保留 5 分钟预热、操作期及 10 分钟静置回收数据。

先完成 30 分钟定位，再跑 2 小时稳定性，发布候选跑至少 8 小时。暂不能完成的物理环境单列，不用短测替代。统计首尾窗口中位数、P95、峰值及 MiB/小时增长趋势，保留原始采样依据；不靠 EmptyWorkingSet 或定时强制修剪制造低数字。

## 二、按资源所有权修复增长

| 审计对象 | 拟实施约束 | 验证方式 |
|---|---|---|
| 图标、字体、位图、DC | 每个 native 对象明确 owner；区分 borrowed/owned，选入 DC 的对象先恢复再释放；错误与窗口销毁路径同样释放 | churn 后对象计数回到稳定带；故障注入不持续增长 |
| 图标/路径/预览缓存 | 记录命中与字节；定义条目数和字节双上限、淘汰与失效策略；窗口消失及时移除；上限按基线确定并写入实现 | 重复相同输入趋稳，大量不同输入仍有界；无 stale HWND/PID 复用错误 |
| Run 建议与后台任务 | 保留最新查询、合并重复任务，限制队列；结果携带 generation，关闭或新输入后丢弃过期结果 | 快速输入、慢磁盘、反复开关不积压，不用每次输入新建线程 |
| 设置/主题/任务栏 | 检查窗口复用、DPI 字体替换、每屏对象与定时器撤销；避免锁内 I/O 和调用其他窗口 | 连续切换无线性 GDI/USER/句柄增长，工作区恢复一致 |
| 更新下载与助手 | 响应、计划文件在读取前限制长度；采用有界缓冲/流式写入并校验；完成后释放网络句柄和线程 | 超长/截断/慢响应、重试、关闭窗口、交接失败；旧版仍能运行 |

基线出来前不批量重构。每个优化必须有“增长原因 → 所有权/上限修复 → 同场景前后对照”，不能仅以换分配器、缩容所有容器或减少功能证明有效。

## 三、稳健性与卡顿隔离

已发现 `hover_preview` 在界面路径同步调用 PrintWindow，是首要响应性风险。该 API 可能阻塞，移到普通线程并设置 UI 等待超时也不能保证底层调用结束。优先评估可取消的预览方案或按需隔离进程；不得在每次超时后遗留一个新线程。无法取得预览时显示简洁占位并保持任务切换可用，预览仍默认关闭。

外部窗口消息、文件/网络访问均需时间和大小边界。UI 不等待未知应用响应，不在持有任务列表/缓存锁时执行外部调用。退出标记取消，异步结果不再触碰销毁窗口；资源释放不能依赖一次成功回调。

更新流程补充故障矩阵：离线、限流、慢响应、连接断开、磁盘不足、不可写目录、重复点击、退出时仍下载、助手/候选进程异常退出、回执超时。只操作本实例创建的目录与子进程；不终止其他会话，不自动申请 UAC。更新备份清理单独设计，只在确认当前版本可用后提供显式操作，不扫描和删除任意相似目录。

配置写入故障保留旧文件及重试入口。日志按大小/数量轮转，诊断有界，默认不记录用户输入和路径。断言、panic 与 unsafe/FFI 边界重点检查；Rust 的内存安全不能替代 Win32 资源生命周期验证。

## 四、UI/UX：诊断保持可选

主设置维持现有三组布局。高级“配置与关于”可增加折叠的“诊断 / Diagnostics”入口：显示简短状态、明确测量起止时间，以及“开始记录 / 停止 / 导出已脱敏摘要”。用户未启动诊断时不创建采样定时器或线程。此入口是 P1，P0 优先交付外部工具及资源修复。

导出前展示字段范围并允许取消；默认只导出版本、指标、场景和结果，不展示内部环境变量名。失败反馈使用可理解文案，技术详情按需展开；中英文、明暗主题、键盘和紧凑布局同步验收。README 只展示通过实测的结果与条件，不提前写“零泄漏”或固定内存承诺。

## 五、交付顺序与验收门槛

1. **P0 证据边界**：原始报告退出版本库，脚本改为本地输出，CI 拒绝原始报告及已知工作站路径；公开摘要和截图人工审阅。本轮已落实，历史副本仍需独立处理。
2. **P0 基线**：可复现外部采样与场景驱动，生成本地曲线和不含路径的公开摘要；在基线上冻结每场景内存、对象计数及响应预算。
3. **P0 修复**：优先处理已复现的持续增长、无限队列和界面阻塞；逐项记录前后对照。预览调用隔离必须验证无法返回的被测窗口。
4. **P1 诊断交互与长跑**：可选界面、2 小时/8 小时观察、故障矩阵，最后完整 release 验收。

开发增加独立 `memory`、`resources`、`fault`、`soak` 层；采样长度和场景可选，`soak` 必须显式给定时长。发布入口统一调度全部层及长跑前提，不能把没有执行的长跑标成通过。现有单元/设置/Run/更新等层继续可单独运行。

暂定回归门槛：相同场景对照基线若私有提交中位数增加同时超过 10% 和 2 MiB，或 GDI/USER/句柄在静置后随循环次数持续增加，阻止发布并归因。预热后重复负载仍持续线性增长、不可恢复卡死、丢配置或破坏工作区均阻止发布。统计阈值只是报警线，不能用于容忍已确认的泄漏。确有必要的有限缓存成本需写明上限和收益，经重新基线验证。

交付物：采样及场景工具、[资源所有权审计表](resources_0_1_10.md)、针对性修复、优化前后曲线、公开验收摘要、未覆盖环境清单；完整发布前不改成“已完成”。

## 新增：左右任务栏可调宽度

用户需求：侧边任务栏支持直接拖宽，纳入 0.1.10。左侧拖右边缘、右侧拖左边缘，边缘 6 DIP 命中区显示水平调整指针；不增加主设置中的数字输入框。默认 180 DIP，共用一个左右侧宽度偏好；上下任务栏继续沿用高度规格。

可调范围 160–480 DIP，并限制有效宽度不超过所在显示器可用跨度的三分之一。小屏按剩余空间进一步收窄，保存逻辑宽度，按每个任务栏窗口 DPI 换算像素。拖动显示宽度预览，松开提交；Esc、捕获丢失、窗口销毁或换边时取消。只在提交时异步保存一次并更新工作区，避免每个像素触发文件写入或系统工作区广播。既有保存失败反馈与重试继续适用。

验收包括左右方向、默认与边界、超出屏幕拖动、取消、重开/重启持久化、DPI 和负坐标显示器几何，以及调整后最大化与退出工作区恢复。配置、DPI/边界几何、拖动预览及异步保存已实现并通过编译与相关单元验证；实机鼠标交互和工作区恢复尚待专项，不宣称已经验收。

### 日志队列归因

依赖的默认非阻塞队列为 128,000 槽位，当前改为 512，饱和丢弃日志而不把磁盘背压传到界面。受控 debug 实验每种容量独立启动三次进程：队列创建前后私有提交增量中位数分别 4,141,056 字节与 32,768 字节，差值 4,108,288 字节（约 3.92 MiB）。只归因于这个初始化路径，不当作整个应用的新基线；优化构建重复实验获得相同差值；整个应用的完整场景仍需对照。阻塞写入器测试验证饱和时调用者不阻塞，并在结束时释放测试 worker。

快捷启动补充：限制原始文件 1 MiB，解析只保留 8 项；读取损坏/超长文件时禁止覆盖。持久化改为同目录唯一临时文件和替换，检查外部修改，失败保留原文件。验证包含替换前故障、非法编码、外部修改及真实文件占用；不据此承诺断电或所有文件系统故障都能恢复。
