# 0.1.12 — Reliable desktop handover


Windows x64.

- Taking over now requires a complete, verified recovery record bound to the Windows account and machine. It preserves the original registry type and bytes, including an absent value. Failed preparation leaves the desktop unchanged.
- Runtime takeover installs the public notification host after the old host exits. Failed handover conditionally restores login settings and reports the observed desktop state. Disk work and process waits run outside the UI thread.
- Essential startup capabilities share one readiness gate. Update receipts and startup success signals are sent only after the message pump is responsive.
- Desktop management separates this session, next sign-in and recovery information. Restore changes next-sign-in settings; the current Minicon session continues running. Unknown third-party shell commands are never started automatically.
- Shell changes use account-wide operation exclusion. Ordinary-privilege operation no longer attempts machine-wide AutoRestartShell changes. Existing clock and Run behavior remain.

Legacy `shell-backup.txt` files are not adopted automatically. If no verified record exists, an explicitly confirmed `--shell-rollback <value|default>` can select next-sign-in settings. Inspect and preserve damaged new records locally before starting a new baseline. Ordinary startup does not modify login-shell registration.

From 0.1.11, use **Check → Update → Restart**. The executable is the exact accepted CI candidate, accompanied by SHA256SUMS.txt and BUILDINFO.toml; code signing is not included. See the [acceptance record](https://github.com/partnernetsoftware/minicon-winmgr/blob/main/docs/validation_0_1_12.md) for completed checks and coverage limits.

# 0.1.12 — 桌面交接与恢复更可靠

Windows x64。

- 接管前必须完整保存并校验当前账户、本机绑定的恢复记录，原始登记类型和字节不丢失；备份准备失败时不改登记、不关闭旧桌面。
- 运行中接管会在旧宿主退出后安装公开通知宿主；失败时按登记实际状态恢复，并如实报告当前桌面结果。磁盘操作与退出等待移到后台。
- 必要界面统一判断就绪，消息循环可响应后才确认启动成功、写更新回执。
- 设置分开显示当前会话、下次登录、恢复依据。“恢复接管前设置”更改下次登录，当前 Minicon 会话继续运行；不会自动执行未知第三方外壳命令。
- Shell 写操作按账户互斥，普通权限下不再尝试写机器级 AutoRestartShell。时钟格式和现有 Run 交互保持。

旧 `shell-backup.txt` 不会被自动采用。无可靠新记录时，可通过显式确认的 `--shell-rollback <原值|default>` 选择下次登录设置；损坏的新记录应先在本地检查并移存后再建立基线。普通启动不会修改登录外壳。

0.1.11 可“检查更新 → 更新 → 重启”。附件原样晋升已验收 CI 候选，附带摘要和构建身份，尚未签名。真实两会话长期所有权、旧记录导入向导、新恢复面板、即时归还第三方外壳、物理设备/无障碍、公网故障及 2h/8h 观察未纳入完成声明。
