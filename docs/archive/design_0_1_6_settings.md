## 体验目标

打开即可理解五项日常设置；修改有即时反馈；需要时能找到配置来源和桌面管理。极简体现在减少重复说明、统一对齐和有节奏的留白，不靠隐藏必要信息或把所有元素压成一列文本。

默认浅色，以系统文字、淡灰背景、白色内容组和细边界建立层级，仅选中与焦点使用蓝色。暂不增加主题设置或依赖 WebView；HTML 仅是设计表达。产品继续用 Win32 原生交互控件，优先实现布局、字体、配色和分组；不为了模仿稿件的开关另建缺少可访问性的自绘控件。

## 页面结构与视觉规格

单页，无侧栏。客户端目标约 600×660 DIP，内容区可滚动、底部反馈固定；工作区较小时缩至可用尺寸。外边距 28 DIP，组间 20，组内横边距 18、行间 12；行高至少 44。标题 24、分组标题 14 半粗、正文 14、辅助说明 12 DIP，使用系统中文 UI 字体。文字按测量换行，不缓存瞬时窄窗口的高度作为永久最小值。

| 层级 | 内容与交互 |
|---|---|
| 页头 | 设置；一句“让任务栏按你的习惯工作”。权限信息放到配置与关于，不在日常页头强调内部状态。 |
| 任务栏 | 显示任务栏、通知区域；短说明紧贴标题。重启项清楚标示“重启后生效”，发生变更时补充当前与下次状态。 |
| 窗口行为 | 合并窗口：从不 / 放不下时 / 始终；合并依据：应用 / 进程；悬停预览。单选组在稿件中有轻底色，在原生实现中保留单选角色和方向键行为。 |
| 辅助入口 | “配置与关于…”单一入口查看每项有效值、来源、文件路径、只读主题/热键、版本和权限。默认来源不逐行重复。 |
| 高级 | “桌面管理”折叠区；展开后解释影响，再提供接管/还原操作，保留现有确认与默认否。初始折叠，不作为默认按钮。 |
| 页脚 | 左侧保存状态，右侧关闭。失败时才出现重试和详情；窄窗允许页脚增高，始终可达。 |

白色表面、背景 #F5F6F8、主文字 #1C2430、次文字 #5B6574、边界 #E1E5EB、选中 #245FCC 为稿件参考值，生产高对比度模式使用系统颜色。先交付可读的浅色界面；完整深色适配另行验收，不承诺只替换背景色即完成主题。避免大阴影、装饰图标、渐变和无功能色块。

## 状态与键盘

- 默认：“更改会自动保存”；保存中：“正在保存…”；成功：“已生效并保存”；涉及任务栏重启时：“已保存，重启后生效”。仍有失败项时，其他项成功不能盖掉失败。
- 失败：“本次已生效，但未保存”并给出重试、详情；不把系统错误码放入主文案。界面稿提供“演示保存失败”以评审状态，此入口不进入产品。
- 环境覆盖：受控行附近显示“由环境变量控制”，保留可读当前值；详情集中在配置与关于。禁用依赖必须说明原因，不能只灰掉。
- Tab 按视觉顺序导航；单选方向键；Space 操作；Esc 关闭弹窗或隐藏设置。展开区若含当前焦点，收起时焦点回到标题。关闭不能误触桌面管理。
- 配置与关于用可滚动对话框承载长路径，支持复制；关闭后焦点回原入口。普通设置不因打开详情触发磁盘写入。

## 管理员启动后的普通权限运行

动机：从提升权限的任务管理器启动，也应让常驻外壳和它启动的普通应用以普通权限运行。这里的“普通用户角色”指同一账号、同一登录会话的非提升令牌，不切换到其他账号、不索取密码。使用原生令牌 API；`runas` 不是本方案的降权实现。

用户补充约束：**程序不主动请求 UAC 或尝试提升权限。** 只读取自己的令牌，已经是普通权限时原进程继续；只有检测到提升权限时才尝试降权。降权失败时显示错误并退出，不以提权重试。应用清单使用 `asInvoker`，启动逻辑不调用 `runas`。

| 入口状态 | 预期行为 |
|---|---|
| 已是普通权限 | 原进程直接继续，零额外启动。 |
| 提升权限且有同账号过滤令牌 | 复制并校验过滤令牌，以它创建自身普通权限子进程。 |
| 无过滤令牌（如某些内置 Administrator / UAC 关闭配置） | 先验证受限令牌方案是否满足同 SID、会话、非管理员有效组和中等或更低完整性。验证不通过则明确失败，不声称已成为普通权限。此分支是技术验证重点。 |
| 无法创建/校验普通权限实例 | 给出简短可操作错误并退出；不静默保持管理员常驻，也不无限重试。 |
| 已有普通权限实例 | 新普通权限进程沿用单实例机制，转交 --settings 等既有请求后退出，不建第二条任务栏。 |

顺序：启动读取令牌 → 判定是否需归一化 → 创建挂起子进程 → 核对实际令牌 → 恢复运行 → 等待有界就绪/已有实例接收结果 → 父进程退出。此前不创建任务栏、占用普通实例互斥体或写配置。父子使用受限的就绪通道，不扩成命令执行入口；正常的配置加载失败应明确传回，不能把“成功创建进程”当作“外壳已就绪”。

使用显式完整 exe 路径、保留原始 Unicode 命令行/当前目录/环境；保持当前用户和会话。候选 API 为 TokenLinkedToken、DuplicateTokenEx、CreateProcessWithTokenW；缺少相应调用权限时核对 CreateProcessAsUserW 的适用条件。CreateRestrictedToken 的 LUA 路径仅作待验证后备，受限令牌不等于另一次标准用户登录。不能依赖 Explorer 存在或启动 Explorer 来降权；不能使用可继承环境开关跳过校验。

子进程校验和就绪失败时清理本次创建的子进程及句柄，父进程只报告失败一次。权限信息可在关于中查看；日志记录阶段、系统错误与结果，不记录完整环境值。管理员专用的接管/还原操作继续走原有受控流程，不能因常驻降权而无提示失效，需在实现前核对这条依赖。

原生行为依据：[进程创建与令牌要求](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createprocesswithtokenw)、[受限令牌](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-createrestrictedtoken)、[提升类型](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ne-winnt-token_elevation_type)。探索代码尚未验证上述全部设计，尤其真实管理员入口、就绪握手及无过滤令牌分支。

## 交付检查

先根据稿件确认信息层级，再实现原生窗口；真实截图核对默认、窄窗、错误、只读和高级展开状态。沿用键盘/UIA、保存失败、Run 和单实例回归。权限功能必须实测普通与提升入口、无 Explorer、参数与环境保留、创建失败和退出清理；现有普通权限环境的测试不能替代管理员入口验证。

资源保持常驻私有字节 ≤20 MiB 目标，不引入浏览器运行时或常驻渲染服务。记录首次打开设置后的缓存成本与 100 轮复用、至少一小时常驻走势；工作集和私有字节分列，截图只展示无用户内容的界面。
