# 更新文件名修复

状态：已纳入[0.1.15 计划](plan_0_1_15.md)，已于 0.1.15 公开交付，准确候选及真实公开更新见[本版验收](validation_0_1_15.md)。0.1.14 标签与附件未改动；其原路径覆盖行为已被用户否定，历史验收记录保留，不再作为新行为的通过条件。

- 官方 `minicon-winmgr-vX.Y.Z-x86_64-windows.exe` 更新后使用目标版本的官方文件名，保持安装目录；不让进程继续显示旧版本名。无版本的固定名和用户自定义名保持其明确命名。
- 新协议区分旧程序与新程序路径，启动回执必须来自新路径的目标版本。已发布的旧 helper 不认识新路径，因此由新程序第一次启动时完成兼容交接，并等待新路径实例真实就绪，不预先伪造回执。
- 新路径已存在或在事务期间被创建时拒绝覆盖。目标没有就绪则恢复旧路径、旧程序与已迁移的登录 Shell；错误保留在原事务目录。
- 仅迁移精确指向旧程序的 HKCU 登录 Shell，使用现有账户操作锁及比较写入；不接管 Explorer 或第三方 Shell，不改原始外壳恢复记录。项目没有创建或登记外部快捷方式；本版不扫描或检测自建快捷方式、计划任务和第三方启动器，也不自动迁移；版本化文件更名后需手动更新这些入口。设置详情与发布说明提供相同提示；固定名/自定义名可保留稳定入口，不声称已覆盖所有启动引用。
- 验证包括正式旧版 helper 到新路径的交接、当前 helper 的交接、名称冲突、不回执回滚、含空格/Unicode 路径、普通权限和原环境恢复；不需要 UAC。

范围不含[原维护草案](plan_0_1_15_maintenance_draft.md)中的旧启动器后台化或存储迁移，也不改写已公开的 0.1.14 附件或标签。

## 验证记录

- fmt、严格 Clippy 与既有质量检查通过；中英 × 并发/串行单元矩阵每组 335 项通过、13 项独立实验忽略。
- 优化版完整更新检查：当前 helper 回移测试与真实公开 0.1.13 基线各 17 项通过，覆盖新路径启动、目标文件冲突、不回执回滚、文件占用、校验失败及设置保持。
- `scripts/legacy_update_path_probe.py` 以真实公开 0.1.14 helper 验证 18 项：含空格/Unicode 目录的新路径实例、普通权限、旧文件名移除、旧版备份、冲突不覆盖，以及改名后新子进程被 Job 进程数限制拒绝时恢复旧路径、旧版本和原 manifest。三轮 helper 均在测试结束前退出，原运行环境恢复；不需要 UAC，也未修改实际登录设置。
- 首轮汇总驱动把隔离配置路径写成相对路径，导致保存失败并出现自有测试实例的未保存提示。只放弃该实例的临时配置后正常退出，原实例恢复；改为绝对路径后整轮通过。专项驱动先后修正了 Win32 verbatim 路径的等价比较、设置控件尚未建完就读取的等待错误，失败报告保留，没有改产品条件来放宽断言。
- 已将一份实际官方 0.1.14 安装从旧版本化文件名更正为当前版本名；预检没有发现指向旧名的标准用户快捷方式、Run/RunOnce 或登录 Shell 引用。更名后实际进程路径、官方文件摘要、普通权限、工作区及注册表不变条件核对通过。此次本机更名与补丁代码交付分别记录，不把它表述成已公开新版本。

原始报告和截图只保存在忽略目录，不提交工作站路径或用户桌面数据。追加单元验证了 UNC/verbatim 登录路径的归一化，未连接实际 SMB 共享。本次修复未重新验证物理多屏、无障碍或此前单次 UAC 退出超时的原因。
