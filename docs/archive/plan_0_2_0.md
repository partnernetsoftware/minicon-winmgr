## 2. 本版本目标与非目标

### 目标（3 条）
1. **日常高频路径更顺手**：常用文件夹一键可达、程序菜单能搜能找最近用过。
2. **通知区可用**：`tray_host` 的图标点击能转发回宿主程序（当前只能看不能点）。
3. **可靠性交账**：完成 ≥ 数小时长跑取证，把"成功度量"里的可靠性指标从 ⏳ 变 ✅。

### 非目标（本版本明确不做）
- 可浏览桌面 / 桌面图标体系（风险大，继续缓；见 [`prd_5_1.md`](../prd_5_1.md) §3）。
- 堆叠窗口组、菜单拖拽整理分类、主题拾色器。
- 打包发版、代码签名、系统级（HKLM）外壳替换——PRD 已列为非目标。
- watchdog 守护进程（用户已明确暂不做；崩溃自恢复维持"下次启动恢复残留"）。

## 3. 选题与切片（按优先级）

### P0-1 文件夹堆栈最小切片 ✅ 最高杠杆
- **理由**：`prd_5_1.md` §1 排序第一，"工作量小、优先级最高"；免开资源管理器。
- **做法**（沿用 [`prd_5_1.md`](../prd_5_1.md) §2/§10 已定方案，**不重新设计**）：
  - 新模块 `src/folder_stack.rs`：`StackEntry`、`pinned()`、`list_dir(path, limit)`、`icon_for(path)`、`open(path)`。
  - `config.rs` 增字段 `folders: Vec<String>`（键 `folders = a;b`）。
  - `start_menu.rs` 在 Places 区之后渲染钉住行，双击调 `open()`。
- **约束**：`list_dir` 用 `std::fs::read_dir`（**无需新增 windows feature**）；展开弹层限
  `MAX_STACK_ITEMS = 15` 条（原生弹出菜单**不滚动**，行数过多会跑出屏幕不可用；首行「打开此文件夹」是去资源管理器看全部的出口）；
  坏路径 `tracing::debug` 跳过。
- **单测（纯函数）**：`parse_folders(s) -> Vec<String>`（空/仅分隔符/去空白/去重）、
  `menu_layout(rows, row_h) -> Vec<RECT>`（边界：rows=0）、`list_dir` limit 截断。

### P0-2 程序菜单：搜索框 + 最近使用专区 ✅（代码已交付；随"菜单默认关"隐藏）
- **理由**：`prd_1_1.md` 标 ⬜，且 `recents` 数据**已经在采**（`launcher` 排序在用），只差在菜单里展示。
- **做法**：
  - `start_menu.rs`：顶部加输入框，输入时过滤应用列表（复用 `launcher` 的匹配逻辑，**抽成纯函数** `matches(query, name) -> bool` 共用）。
  - Places 之后加"最近使用"区，取 `recents` 前 N（默认 8，常量化）。
- **约束**：菜单渲染仍在消息线程，**不新增 worker 线程**；`recents` 读取属文件 IO，**锁外做**。
- **单测**：`matches`（大小写、子串、空 query）、`recent_rows(entries, limit)` 截断与排序稳定性。

### P1-1 通知区点击转发 ➡️ 已移交 v0.1.3
- **状态**：**不在本版做**。做在 [`plan_0_1_3.md`](plan_0_1_3.md) 的 **P0-2 托盘收敛**里（含"单一数据源 + 真图标 + 点击转发"三步）。
- **移交理由**：调研发现托盘问题**根子是耦合**——`tray.rs`（镜像）与 `tray_host.rs`（宿主）是同一功能的两套数据模型，
  任务栏只接了废的那套。零散修 `tray_host` 而不统一模块，等于在死代码上加功能。
- **原做法（保留备查）**：`tray_host.rs` 记录 `hWnd` + `uCallbackMessage` + `uID`，点击时 `PostMessage` 回投
  ——**该实现在 0.1.3 开工前已存在**（`forward_at`/`forward_to`/`StripLayout::hit_test`，整段挂着 `#[allow(dead_code)]`）。

### P1-2 质量债两小项（顺手清）
- **设置项依赖置灰**（`prd_6_1.md` §9「应该」）：关掉"显示任务栏"后，合并相关项置灰并写明依赖。
- **UWP 过度合并**（`prd_6_1.md` §13.3）：`ApplicationFrameHost.exe` 会让多个 UWP 应用被并成一组。
  缓解方向：`group_by=exe` 时对 `ApplicationFrameHost` **回退按 pid/窗口标题**区分（需先小范围实测再定，
  **若影响面过大则维持现状并把结论写回 PRD**，不强行改）。

### P2 稳定性长跑取证（非功能，但决定能否把门槛项转 ✅）
- **做法**：以 release 构建常驻 ≥ 4 小时，借 `metrics` 日志核对 `handles`/`gdi_objects` 持平、无 panic、
  消息泵不卡死；记录起止值与结论。
- **产出**：把结论写回 `prd_2_1.md` §2 与 `prd_3_1.md` §2 门槛第 7 项。
- **不引入新代码**：如发现泄漏再单独立项。

## 4. 分期与并行分工

沿用 [`prd_5_1.md`](../prd_5_1.md) §11 工作方式：**大改动拆并行 subagent，每个只改唯一文件**；
接线由主代理单点做。

| 波次 | 内容 | 负责文件（唯一） | 说明 |
|------|------|------------------|------|
| W1 | 文件夹堆栈 | `src/folder_stack.rs`（新） | 纯逻辑 + 单测，禁起 GUI |
| W1 | 菜单匹配纯函数 | `src/launcher.rs` | 抽出 `matches()`，不改既有行为 |
| W2 | 配置字段 | `src/config.rs` | `folders` 解析 + 默认值 + 单测 |
| W2 | 菜单接线 | `src/start_menu.rs` | 依赖 W1/W2，主代理做 |
| W3 | 通知区点击转发 | `src/tray_host.rs` | 可独立并行 |
| W3 | 设置项依赖置灰 | `src/settings_ui.rs` | 可独立并行 |
| W4 | 长跑取证 | 无（运维） | release 常驻，读日志 |

subagent 通用禁令（照抄 PRD）：禁改 `Cargo.toml`、禁 `cargo add`、禁 `cargo fmt`、禁起 GUI；
可跑 `cargo check`；**纯逻辑必须带单测**。

## 6. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 文件夹堆栈 IO 卡消息线程 | 限 64 条；坏/慢目录 `debug` 跳过；IO 锁外 |
| 图标句柄泄漏 | `DestroyIcon`；`metrics` 监控 GDI |
| 菜单搜索改动波及 `launcher` | 只**抽出**纯函数复用，不改既有排序/检索行为；V1 兜底 |
| UWP 合并缓解影响面不可控 | 先小范围实测；不行就维持现状 + 结论回写 PRD |
| 通知区回投语义不准 | 只转发单击/双击/右键；异常一律降级 + 落日志 |
| 长跑期间出泄漏 | 不阻塞发版，但单独开项修，并把 V7 作为回归门 |
