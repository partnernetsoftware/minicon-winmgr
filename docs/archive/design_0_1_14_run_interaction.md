## 1. 目标与依赖

用完整任务而非零散按键补丁，确定输入、预览、确认、执行和失败修正之间的一致关系。继承前版的测试隔离与启动基础；本版不依赖 0.1.15 的旧启动器重构，可按讨论结果调整顺序，但不能跳过必要基础验证。

## 2. 先完成五条任务走查

| 任务 | 要观察的问题 | 形成的验收样例 |
|---|---|---|
| 输入短命令直接运行 | 输入完成后是否可直接执行，候选出现是否改变默认动作 | 无选中项时 Enter 运行当前文本，候选不会自行替换或执行。 |
| 重用带参数历史 | 上下键后实际将执行什么，是否存在没有解释的二次确认 | 高亮、输入内容、按钮与 Enter 行为一致；候选来源不改变规则。 |
| 选择后追加参数 | 光标/选区是否符合继续编辑预期，重新匹配是否跳动 | 追加/删除/粘贴按已确定规则编辑当前命令；旧查询不能覆盖新输入。 |
| 选择目录后继续补全 | 目录、含空格路径及参数是否保持正确，下一层建议何时出现 | 目标补全与参数分离，保留引号和原参数；明确何时提交目录预览及何时请求下一层。 |
| 启动失败后修正 | 原文、光标、焦点和错误提示是否能支持立即修正 | 失败不隐藏、不写成功历史；重新编辑清除过期错误，重复提交受控。 |

覆盖历史、路径、应用三种来源；同时记录鼠标与键盘的实际动作，不用新增“采用”文案掩盖行为分歧。

## 3. 讨论后确定一个模型

比较现行“两次 Enter：先采纳再执行”与“明确选中后一次 Enter 执行”两种方案。讨论材料须列出每条任务的操作序列、执行点和取消结果；在用户确定前保留现有行为，不能把其中一种预先写成已批准需求。

最终模型必须同时说明：

- 没有候选、列表出现但未选中、预览选中、手动编辑、提交中、失败六种状态下的 Enter/Tab/Esc。
- 下拉按钮和 Alt+↓ 如何展开/收起，列表边界如何导航；收起、Esc、外部失焦、关闭是否提交或撤销预览。
- 候选采用后输入框选区/光标位置，以及继续编辑与下一层路径建议的触发时机。
- 鼠标单击/双击候选是否与键盘确认具有相同执行含义；不保留未说明的例外。
- 中文 IME 组合输入优先处理 Enter/Esc/方向键；窗口内部切焦点不误判为外部失焦；提交中不重复执行，旧回复不覆盖新草稿。

设计产物是一份行为表与少量关键任务示例。先更新现行 Run 规格，再改实现和提示文案；避免在本计划复制第二份长期维护的 Run 规格。

## 4. 实施与验收边界

保留 Win32 原生输入、选择、复制/粘贴、撤销和可访问语义；启动继续经过 `shell_launch`，不改目标解析、Explorer 保护和普通权限要求。不引入浏览/提权按钮、联网搜索、全盘索引或新的命令语言。

先以隔离原生控件 fixture 覆盖状态转换、过期查询、重复提交和草稿保护，再对准确候选执行五条任务的真实输入走查，中英文与明暗主题、键盘/鼠标及可用 IME 环境分别记录。只向控件发送模拟消息不能证明真实 IME 完整可用。

完成条件是行为表与实现一致、用户对关键任务试用结果有明确反馈、功能回归通过；不能只凭单元测试将 UX 标为已认可。工作区、长跑与未具备的物理设备矩阵继续单独记录。

旧启动器/recents 后台化及剩余资源边界见 [0.1.15](plan_0_1_15.md)。本页当前只安排走查与待确定设计，没有授权某一种新的按键行为。
