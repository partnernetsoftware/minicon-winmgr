## 1. 用户任务与取舍

用户通常只想做三件事：输入 `notepad` 或 `cmd /c ...` 马上运行；粘贴路径/网址打开；重复上次的长命令。现状要求反复输入，执行失败却消失，用户无法纠正。优先保证“输入 → 执行 → 出错可修改”闭环，再用历史和路径补全节省按键。

本版做 R1–R7；不扩成 Alt+Space 应用搜索，不做浏览按钮、提权按钮、插件、联网搜索、全盘索引、参数智能补全。保留原热键注册和回退规则；不借此修改系统热键、注册表或接管状态。

## 2. R1：布局与入口

```text
┌ 运行                                      × ┐
│ 输入程序、文件夹、文档或网址                  │
│ 打开(O)：[                              ▾ ] │
│ ┌ 最近使用 / 路径建议（有候选时展开） ─────┐ │
│ │ cmd /c "echo hello"              最近  │ │
│ │ C:\Examples\                          文件夹│ │
│ └────────────────────────────────────────┘ │
│ 找不到程序。请检查名称或路径后重试。          │
│ 清空历史                     [运行] [取消]  │
└────────────────────────────────────────────┘
```

- 标题“运行”，所有固定文案中文；系统编辑控件保留选择、复制/粘贴、撤销、水平滚动及 IME 行为。布局服从系统主题/高对比度；不为统一深色牺牲原生输入可读性。
- 参考宽 480 DIP、内边距 16 DIP、间距 8 DIP、输入高至少 28 DIP、按钮至少 72 × 28 DIP；字体采用系统 UI 字体。候选最多显示 6 行，可滚动；错误区域按文字换行增高。尺寸是设计起点，不能用裁字来硬凑。
- 呼出立即置前并聚焦输入框。首次为空；成功后下次显示最近成功命令且全选，直接输入即可覆盖。取消/失焦留下的草稿在本会话下次呼出恢复并全选，不持久化草稿。
- 已显示时再次按热键只置前、聚焦并全选，不清空、不关闭；取消、×、Alt+F4 隐藏复用窗口。点击其他应用关闭候选并隐藏对话框，保存会话草稿。

## 3. R2：键盘、焦点与 IME

| 操作 | 规定行为 |
|------|----------|
| Enter（输入框） | 有明确选中候选时先采纳该项并收起列表，再按 Enter 执行；无选中项时执行当前输入。默认不选候选，避免误运行 |
| ↑/↓ | 候选已展开时移动选择，并同步将候选完整文本预览到输入框，光标置末尾；列表保持展开，焦点留在输入。保留开始选择前的草稿和选区，预览不触发新查询、不执行。未展开时打开匹配历史（空输入显示最近项） |
| Alt+↓ / 输入右侧 ▾ | 展开/收起历史候选；不执行 |
| Esc | 候选展开时先收起，撤销预览并恢复原草稿和选区；否则隐藏对话框。未采纳预览在关闭或失焦隐藏时也恢复草稿 |
| Tab / Shift+Tab | 输入 → 清空历史（有历史时）→ 运行 → 取消，正反循环；列表不抢 Tab，不用 Tab 补全 |
| Alt+O | 聚焦并全选输入；Ctrl+A/C/V/Z、Home/End 等保持编辑控件默认语义 |
| 点击候选 | 采纳文本、收起列表、焦点回输入；不会直接运行 |
| 按钮 | Space/Enter 激活聚焦按钮；空白输入“运行”置灰，无启动调用 |

IME 组合输入和系统候选窗优先处理 Enter/Esc/方向键，组合期间不执行、不隐藏、不刷新自有候选；组合结束后再匹配。输入框、按钮、候选列表之间切焦点，以及 IME 候选窗出现，不得被当成点击外部而隐藏。控件有可访问名称和可见焦点指示，键盘可完成整个流程。

在预览文本上继续输入、删除、粘贴或开始 IME 组合时，以当前文本继续编辑，结束本次预览并重新匹配；之后 Esc 不回退这次手动编辑。Enter/“采用”仍先确认候选并收起列表，再次 Enter 才执行；单击候选直接采纳，不执行。Alt+↓ 或 ▾ 收起列表时同样撤销未采纳的预览。

## 4. R3：命令语义与外壳保护

- 保留用户输入文本，去掉首尾空白，不再无条件剥除整串引号。解析得到“目标 + 原样参数”；参数引号、空格和反斜杠不重写。支持引号包裹的含空格程序路径，如 `"C:\Program Files\App\app.exe" --name "张 三"`。
- 完整输入（可整体带引号）若是现存文件/目录，则作为单个目标，即未加引号的 `C:\Program Files` 可打开；否则未加引号的命令按首个空白分目标和参数。含空格程序路径附带参数须给目标加引号；不猜测最长可执行前缀。未闭合目标引号提示“引号未闭合”，留窗。
- 裸程序名通过 Windows 的正常启动解析打开；文档用系统关联；文件夹用浏览器打开；`https://...`、受系统支持的 URI、`shell:` moniker 按完整目标处理，网址内的查询参数不拆成命令参数。
- 顺序：先对完整输入做“单个文件/目录”判定（允许为这一判定展开环境变量，不改原文）；不成立时，按**原文**引号/空白界定目标片段，再分别展开目标与参数中的已定义 `%NAME%`。展开后的空格不会再次拆分：`%ProgramFiles%\App\app.exe --x` 与 `"%ProgramFiles%\App\app.exe" --x` 都得到完整程序目标和原样 `--x`。直接书写含空格目标且附参数仍须引号。未定义变量保留并在失败时说明。0.1.6 按用户反馈修正：参数中的已定义环境变量也展开一次，原有空格、引号和反斜杠保留，不递归展开；例如 `notepad %USERPROFILE%\.workbuddy\models.json`。若展开值含空格，仍可显式给参数加引号。文档直接打开依赖系统文件关联，缺少关联时明确报错；不擅自修改默认应用。不承诺 `~`、PowerShell `$env:` 或 shell 内建命令隐式可用。
- `cmd /c "echo hello"`、`control.exe timedate.cpl` 必须拆成正确目标和参数；`dir`、管道、重定向、`&&` 不隐式套 `cmd`。批处理目标交给系统正常关联，失败仍可见。
- 相对路径基准明确为用户配置文件目录（`%USERPROFILE%`），通过启动请求显式传递，不随 exe 所在目录漂移；缺少基准时报可修正错误。
- **所有启动仍经过 `shell_launch`**，统一扩展其带参数/错误结果接口，旧调用者保持原行为。在目标解析、去引号和环境变量展开之后识别裸 `explorer` / `explorer.exe` / 绝对路径：没有实质参数（空参数/空白）时补“此电脑”参数；有文件夹参数时正常打开。此约束是本程序直接启动的 Explorer 保护，不承诺检查用户显式 shell 命令内部的任意脚本。
- 不新增散落的 `ShellExecuteW`、`cmd /c start` 或绕过已启用 Windows feature 的 `link!`；遵守 [`prd_2_1.md`](prd_2_1.md) §5 第 5、13 条。

## 5. R4：失败反馈与提交状态

输入无效或启动 API 返回失败时，留窗、留原文、焦点回输入且保留光标，不写历史。输入下方显示可操作错误：找不到目标、路径不可用、没有默认打开方式、权限不足或其他启动失败（附错误码）。日志保留失败分类和代码，UI 不要求用户去查日志。用户修改输入时清除旧错误。

提交处理中显示“正在打开…”，禁用重复提交，输入/取消保持响应；同一次请求只启动一次。API 接受启动请求后才关窗并记录历史，不能据此宣称应用已成功完成任务。取消/失焦发生于提交中时，隐藏并丢弃后来 UI 更新，不承诺终止已提交的外部应用。

## 6. R5：历史与候选

- 独立运行历史按成功提交时间倒序，最多 30 条，保留原始完整文本；仅完全相同文本去重后移到首位，不把不同参数或大小写擅自合并；不混入启动器频次排序。
- 保存在当前用户 `%LOCALAPPDATA%\minicon-winmgr\run-history.json`；写入用临时文件替换，读取损坏/不可写时降级为会话历史并记日志，不影响运行。参数可能含敏感文本，因此“清空历史”常驻于有历史时，操作清空内存和磁盘；磁盘处理完成才提示成功，失败明确提示“本次历史已清空，磁盘历史清除失败，重启后可能恢复”，并保留重试入口；不将输入同步到外部。
- 空输入/手动下拉显示最近项；输入非空时按完整历史文本的不区分大小写前缀匹配，最近优先。不匹配则不显示历史，不拿“最近一条”替换用户文本。
- 本版路径建议只补首个目标：已输入明确的本地绝对目录前缀时枚举该目录一级，目录优先再按名称排序，最多 20 项；不扫描 PATH、不递归、不补参数。目录项采纳后加尾部 `\`，文件项采纳为完整路径，含空格时按目标语义加引号。采纳仅替换已定位的目标片段，既有参数及其空格/引号原文完整保留；无法可靠界定目标时不提供路径建议。
- 候选来自历史或路径时标明来源；相同文本只显示一次，历史在前，总数最多 20 项，首屏最多 6 行。建议出现时不自动选中或覆盖输入；用户明确按上下键选择后按 R2 预览文本。

## 7. R6：DPI、多屏与窗口生命周期

按呼出前前台应用所在显示器的工作区放置：水平居中、上四分之一；前台无有效显示器则选鼠标所在屏，再回退主屏。整体夹入工作区，不压任务栏；屏幕太小时先减少候选可见行，保留输入和按钮。

布局/字体按目标显示器 DPI 换算；处理 DPI 变化和显示器拔插，重新夹入存活工作区。每次呼出重新计算位置；显示/隐藏复用控件资源，关闭退出时释放字体、列表及异步状态。

## 8. R7：性能边界

- 目标：热启动呼出到可输入 ≤100ms；输入反馈/取消 ≤100ms；连续 100 次呼出取消后句柄/GDI 无持续增长。0.1.4 已作真实桌面采样；结果与测量边界见版本计划 §3，不将单机样本当成所有环境保证。
- 历史读写、路径存在性检查、目录枚举和可能阻塞的启动调用不得拖住消息线程。建议采用运行模块独立的有界后台执行器，最多一个运行中的补全查询、一个最新待处理查询；新输入去抖 150ms，以请求代号丢弃过期结果。后台不读取/修改 taskbar 锁或操作 UI HWND，结果经消息回到 UI。
- 路径查询 500ms 内无结果便结束本次等待，界面显示“路径建议暂不可用”并允许继续编辑/运行；底层 IO 可能不能中止，不能靠超时重复创建线程。仍占用时跳过新的目录查询，不能堆积；退出不等待慢盘完成。
- UNC、网络映射盘及可移动盘本版不自动目录补全，仍允许用户显式打开；本地盘也可能很慢，依然遵守上述边界。候选列表只呈现已取得的数据，不为首次呼出同步扫描磁盘。
