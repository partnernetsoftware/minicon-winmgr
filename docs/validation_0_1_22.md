# 0.1.22 验收记录

本版修复 0.1.21 公开后发现的缺陷：替换模式下选择纯色桌面颜色后不生效。根因与证据见 [0.1.21 验收 §6](validation_0_1_21.md#6-公开后缺陷)，计划见 [plan_0_1_22.md](plan_0_1_22.md)。

## 1. 准确候选

- 候选运行 `40450512982`，源码提交 `84c7d65`，源码指纹 `b57223a7…`（与本地一致）。
- Winmgr `6d98c6ff…`，Tskmgr `f85a3d9b…`，与候选附件和 `BUILDINFO.toml` 一致。
- 候选基于 `4b7ae71`（白名单修复）之后增加了仅测试代码的持久化检查，因此采用最后一次候选；前一个候选 `40449699184` 仅用于全屏层的初步核对，不作为发布依据。

## 2. 根因修复与单测

- `settings_store` 的写入白名单加入 `desktop.color`，白名单判定抽为纯函数 `is_ui_key`，并有直接单测 `desktop_colour_is_a_ui_key`。
- 完整普通单元层 346 项通过，0 失败；质量门禁通过；格式与公开文档边界检查通过。

## 3. 私有桌面证据

- `isolated_tray_probe.py --test surface`（源码构建的测试二进制）通过：颜色先经配置写入并落盘（`desktop.color` 与 `#1E3A5F`），随后纯色窗口铺满虚拟屏、命中测试正确、窗口 DC 读回颜色一致、换色和隐藏生效。
- 该测试在私有桌面运行，不改动用户当前会话的外壳。

## 4. 候选桌面层

- 全屏让位层（`--layer fullscreen --candidate-exe`）：6 项通过，原外壳恢复。
- 设置层（`--layer settings --candidate-exe`）：候选失败于 Tab 顺序检查 `native_tab_sequence_skips_disabled_radio_basis`；同一层对照公开 0.1.21 也失败（AssertionError），本机在此时段属于桌面焦点不稳定，未能确认为代码回归。此前 0.1.20 对照与 0.1.21 候选分别有通过的运行记录。

## 5. 覆盖限制

- 颜色选择框是模态对话框，没有自动化驱动；“点击颜色并确认 → 颜色出现”的完整路径需在真机替换外壳中人工确认。
- 显示器热插拔、物理多屏、Win+D 与“显示桌面”按钮在纯色桌面上的表现未单独验证。
- 设置层在本机的失败未定位，不能声称设置层已在本机稳定通过。
