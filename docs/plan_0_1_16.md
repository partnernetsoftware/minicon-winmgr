# 0.1.16 计划：Tskmgr 我的任务

状态：开发中，已完成只读查询核心和独立采样原型；原生 GUI、管理动作与多产物交付尚未完成，未发布。前置 .15 已公开交付。更新：2026-10-20。需求唯一来源：[工具 PRD](prd_7_1.md)。

## 1. 目标与依赖

用户能从 Winmgr 的窗口找到对应进程，也能独立打开 Tskmgr 管理自己的任务。普通权限优先，先把列表、定位与操作反馈做可靠。

建议在 [0.1.15](plan_0_1_15.md)公开并完成真实旧版更新后进入本阶段。版本号指 Winmgr 集成里程碑，Tskmgr 首发版本号另定，不预设它也叫 0.1.16。

## 3. 不纳入本阶段

管理员管理、进程树批量结束、进程实时网络速率、断开/阻断联网和防火墙写入进入后续设计；不建设插件平台、不安装服务或驱动、不新增 Sysmgr 主界面。权限不足时给出限制，不能为完成列表而提权整个外壳。

## 4. 完成条件与拆分规则

任务树按准确候选验证通过，独立工具和 Winmgr 集成均可用，外壳生命周期不受工具退出影响。多 exe 更新交付方案必须在开发前确定；当前单 exe 更新器不视为现成支持。

按用户已授权范围完成普通进程管理、基础网络视图与交付契约，不因当前测试便利缩减；确需调整时明确说明未完成项。UAC 管理入口在下一阶段具备能力后才展示。

## 测试范围的当前约定

按[风险选择规则](testing.md#当前规则2026-10-20)执行：只为本版变化及依赖边界收集必要证据，复用未改动能力的历史结果；不默认全套桌面回归或重复语言/并发矩阵。准确候选、权限/目标身份、失败恢复及真实公开交付仍须核实；通过项数量不作为质量指标。

## 首期交付契约（2026-10-20）

- 同仓增加独立 `minicon-tskmgr` 可执行目标；首期与 Winmgr 使用同一发布版本以简化维护，不建立永久同步版本的约束。独立进程、独立入口与独立生命周期不变。
- candidate 一次构建两份 exe，发布清单同时绑定摘要；公开两份版本化文件和校验表。更新器继续兼容旧版单 exe 交接，不把工具存在视为外壳启动前提。
- Winmgr 工具入口优先使用已校验的对应版本工具；缺失时明确提供“下载并打开”，由有界后台任务从对应公开 tag 下载并校验，再原子放入版本化工具缓存。失败可重试，不阻塞外壳，不从任意 PATH 猜测程序。
- 工具可从公开附件独立下载运行，无需 Winmgr。Winmgr 更新不覆盖正在运行的旧工具；每个工具窗口显示自己的版本，后续入口选择对应版本文件，不把旧进程显示成新版。
- 查询/动作与 GUI 分离，Windows 适配集中；先实现可直接采样的核心及无 GUI 冒烟，再接原生视图。网络端点依微软公开 IP Helper API；进程命令行按可用数据源提供，不伪造不可读值。

首期网络数据源：[TCP owner PID 表](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getextendedtcptable)、[UDP owner PID 表](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getextendedudptable)。这些接口提供端点及归属，不提供进程实时流量，后者仍属于 .17 的独立评估。

## 开发进度：只读核心原型

已增加独立可执行目标与平台无关的数据结构，Windows 适配负责进程 SID/会话、创建时间、路径、CPU 采样和内存，以及 IPv4/IPv6 TCP/UDP owner PID 表。进程身份使用 PID + 创建时间；网络归属在读取后复核，UDP 不伪造远端与状态，不可查询字段保持缺失。

定向验证：编译通过；PID 复用/计数回退规则通过；自有 Python 进程与本地 IPv4/IPv6 的监听、已建立 TCP 和 UDP 端点被正确采样，归属和内存核实，单次本机采样约 0.11 秒。此结果只证明开发核心原型，不是 GUI、管理动作、CPU 长期采样或正式候选验收。测试不切换外壳、不请求 UAC；原始快照只留忽略目录。
