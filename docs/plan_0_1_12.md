# 0.1.12：可靠接管、统一就绪与准确恢复

状态：**选定范围已实现，准确候选验收完成，发布流程进行中**。更新：2026-10-18。用户授权开发到公开发布并根据实际情况调整计划；基于公开 0.1.11 和 main `96f5c50` 实施。

项目以完成 0.1.x 基础能力、修复可靠性问题为主；不默认继续扩展新功能或 macOS 产品。[完整设计稿](design_0_1_12.md)保留探索范围，本页列出本版实际交付与边界。0.1.13–0.1.15 仍是备选资料，不构成逐版实施承诺。

## 1. 用户结果

- 恢复依据未成功保存并校验前，不改登录 Shell、不关闭旧桌面。
- 成功接管必须补齐公开通知宿主；失败按本次实际改动恢复，分别说明登录设置与当前桌面结果。
- 必要界面未就绪时，各启动入口均不确认成功；消息循环收到工作后才发成功信号和更新回执。
- 设置沿用两项动作，分别显示当前会话、下次登录、恢复依据。“恢复接管前设置”更改下次登录；当前 Minicon 会话继续运行，不承诺立即交还第三方外壳。

## 2. 已继承与兼容决策

0.1.11 已[公开发布](https://github.com/partnernetsoftware/minicon-winmgr/releases/tag/v0.1.11)。继承普通权限重启、时钟格式、Run 候选预览，以及格式、公开路径、英文断言隔离和测试 socket 模式修复；不重复作为本版新增功能。

旧 shell-backup.txt 不自动导入，也不把空文件、记录缺失、损坏或异身份当作同一状态。无有效新记录时保留明确的手工路径：显式确认 --shell-rollback <原值|default> 选择下次登录设置，再接管。损坏的新记录需本地检查并移存，不能静默覆盖。原第三方命令不自动执行。

同账户不同会话共享登录登记，因此所有写入口按账户互斥并在写前对照实际值。本版没有实现跨会话长期所有权管理；操作互斥不能宣称已解决所有多会话共同接管策略。

## 4. 验证与发布条件

完整结果、准确构建和实际边界统一记录于[验收记录](validation_0_1_12.md)。记录与条件恢复先在临时目录/抽象层验证；真实 Win32 登记读写仅使用临时测试键。独立且从不激活的测试桌面，加仅测试进程的 HKCU 重映射，验证损坏记录零副作用、旧宿主退出后安装失败回滚、重试成功、恢复登录设置但保留当前宿主；不向实际登录设置注入故障。

启动门槛与确认顺序由单元验证，消息循环和后台/UI 转换由原生 fixture 验证。它们不冒充所有真实 Win32 创建失败、管理员策略或两会话矩阵通过。

CI 构建候选一次，对同一 SHA-256 文件执行完整功能层、公开 0.1.11 更新/回滚和官方 0.1.4 双语替换，核对原程序、工作区、登录设置恢复。通过后合 main/tag，由 tag workflow 原样晋升已验收 CI 文件为草稿，核验附件后公开，并验证实际公开旧版更新。源码变化重建候选，旧证据不冒充新摘要通过。

## 5. 本版未实施与覆盖边界

- 旧备份导入向导、跨会话长期所有者/失效所有者接续、成功接管后主动即时归还任意第三方外壳、新恢复面板，均留在设计参考中。
- 工作区、pins、recents 的身份/路径迁移与响应性不在本版；窗口搜索、固定命令、置顶、布局快照和 macOS 扩展不新增。
- 2h/8h、完整资源多场景对照、物理 DPI/热插拔、高对比度/屏幕阅读器、真实 IME、特殊管理员令牌、公网故障与真实两会话矩阵仍独立跟踪，不据短测宣称稳定认证或零泄漏。
