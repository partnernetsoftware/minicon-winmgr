# 0.1.12 计划讨论稿：桌面交接有结果，失败后有退路

> 产品收口（2026-10-18）：winmgr 以 0.1.x 的基本够用与可靠收尾为目标。0.1.11 已公开发布；0.1.12 从已确认的可靠性缺陷中选择必要修复，不默认实施下述全部设计切片。0.1.13–0.1.15 保留为备选资料，不再默认逐版推进；窗口搜索、固定命令等新功能及 macOS 扩展均不进入当前计划。

状态：**实施中，目标公开发布 0.1.12**。更新：2026-10-18。用户授权根据实际情况调整计划；以 [0.1.11 公开版](https://github.com/partnernetsoftware/minicon-winmgr/releases/tag/v0.1.11)及 main `96f5c50` 为基线，保留 Run 现行交互。

### 本轮选定范围（优先于下方完整设计切片）

- C01/C06：接管前必须完成账户 SID/本机绑定、原始类型与字节的不可覆盖恢复记录；失败零接管副作用。所有 Shell 写入口共享账户级跨会话操作锁，CLI 登记操作保持不动宿主。
- C02：必要界面结果统一，消息循环实际响应后才确认降权、实例替换及更新成功；必要失败不确认，并让现有协调者回退。
- C07：共同运行转接管时，在持久化之后关闭已核验的同用户、同会话旧宿主，安装公开通知宿主、广播重登记；失败对照本次快照恢复并分别报告结果。CLI 即时接管由持续运行的 UI 实例执行。
- C09 局部/12-05：现有两项动作及三行状态准确表达当前会话、下次登录和恢复依据；恢复不自动执行未知第三方命令，不承诺立即交还当前会话；普通权限下停止尝试 HKLM。
- C03：继承 .11 已完成修复，补普通 CI 完整单元与本次恢复/就绪故障验证。

本版采用工程上的最小完整范围：成功接管后的主动即时归还、旧记录导入向导、跨会话长期所有权与新恢复面板暂不实施。旧记录不静默导入；无有效新记录时，保留明确的手工显式 `--shell-rollback <value|default>` 路径后重新接管。跨会话本版只做操作互斥与当前登记条件检查，不宣称长期所有者机制或真实两会话矩阵已实现。异常唯一登录 Shell 使用最后可用错误反馈并非零退出，不声称已提供完整恢复 UI。

对应验收：D01–D04（选定的记录/登记/过程失败）、D05（操作互斥）、D08–D09、D11–D14、D15–D16。D06 长期所有者、D07 导入向导、D10 新恢复 UI 留作后续设计，不作为本轮未实施能力的完成声明。下方完整切片与设计矩阵保留作参考，不默认扩大发布范围。

## 1. 用户结果与边界

本版让用户准确知道当前桌面由谁管理、下次登录会用什么，以及交接失败后恢复到了哪一步。沿用设置的接管和恢复入口，加三行状态与准确结果；不增加常驻操作面板。

建议优先保留的修复结果：可靠恢复依据是接管前置条件；必要界面未就绪不向任何启动入口确认成功；若本版修改共同运行后的接管流程，须同时处理真实通知宿主转换；中途失败按实际已发生的变化恢复，结果如实呈现。选定改动先取能完整解决问题的最小范围，不将复杂迁移向导或新界面自动列为必要交付。

建议本版不扩大到成功接管后对任意第三方外壳的当前会话即时归还。现有恢复入口应准确说明当前与下次登录分别发生什么，不能继续把仅改登录设置称为“立即还原”。是否要求 Minicon 主动释放宿主并立即交还 Explorer，见设计稿最后的集中取舍。

响应性/工作区记录的备选设计见 [0.1.13](plan_0_1_13.md)；Run 行为走查见 [0.1.14](plan_0_1_14.md)；旧启动器、pin/recents 和其余资源边界见 [0.1.15](plan_0_1_15.md)。这些不构成连续版本的交付承诺。窗口搜索、固定命令、置顶和布局快照不加入本版。

## 2. 先接收 0.1.11 实际发布结果

开工前检查 .11 最终 main/tag、产品差异与准确候选证据。已经修好的 fmt、公开路径、语言隔离等门槛直接继承；尚未完成的测试环境隔离/双语并发和 CI 覆盖才进入本版。不能把“发布任务已安排”当作已通过，也不在 .12 文档中替 .11 宣布发布。

2026-10-18 发布 agent 同步：发布隔离分支已提交四个 `shell_launch` 英文断言的独立子进程/显式英文环境、`logging.rs` 格式、虚构 `shell_registry` fixture 路径及 HTTP 测试 socket 阻塞/超时修复，并报告 316 单元与 quality 通过；还修正侧栏边界和 Run 焦点探针。上述按最终发布提交接收，不能继续列为 .12 待修；该同步不是 .11 已合并/公开或全部双语隔离已完成的证据。

普通权限自重启、时钟格式和现行 Run 交互按 .11 实际交付继承，不重复实施。记录 .11 的新缺陷时依据实际提交/失败证据调整计划，不拿历史审阅行号当最新源码。

12-02 与 12-04 同版交付，不能只修文件写入然后宣布接管完成。12-05 随前四项实现，不是可删除的最后润色。错误只补本流程需要的固定分类与数值 Win32/HRESULT，不做全局错误体系重写。

账户共享 HKCU 与会话宿主各自有责任；.12 不顺便迁移工作区、pins 或 recents。记录不能证明身份时拒绝自动改登记，但必须有明确可取消的修复路径，避免做成永久锁。所有 Shell 写入口共享身份/记录/竞争保护，低层只改登记 CLI 保持只改登记，不因此关闭或启动宿主，也不新造 CLI 产品。

## 4. 实施顺序

1. 对照 .11 最终结果补基线；确认三项产品取舍，将行为归位到 Shell/可靠性/通知区/设置 PRD。
2. 临时目录与注册表抽象完成恢复记录、精确保留原值、竞争/崩溃/迁移 fixture；所有写入口进入同一账户协调逻辑。
3. 统一必要能力与消息循环 Ready，验证各启动来源及唯一回退协调者；对无外部协调者的唯一登录外壳故障补尽力恢复入口，不阻止旧更新器回退。
4. 在消息线程的明确生命周期内补接管通知宿主转换、外部宿主退让和失败恢复；文件/等待阶段不持 taskbar 状态锁，不让设置失去响应。
5. 对同一准确候选执行真实可恢复桌面、旧版更新/替换和中英文操作走查；复核三行状态、按钮文案与实际结果。

不通过“看到 HWND”“有备份文件”“CreateProcess 返回成功”“有任意图标数”替代相应能力证据。无图标的干净会话也应能成功；真实图标协议与回调用专项探针验证。

## 5. 完成条件与发布

实施前明确选定切片与设计稿 D01–D16 的对应关系；这张完整矩阵是审阅参考，不把未纳入范围的新增能力变成默认发布门槛，也不把未执行项记为通过。已选范围的关键故障（无备份、异身份、初始化失败、宿主失败、恢复失败等）先在 fixture 验证，真实桌面独占且有恢复程序；不得在用户实际登录设置上注入故障。

准确候选通过质量、优化普通单元、相关故障层、真实完整功能、历史更新与替换回归后，按现有“候选构建一次 → 验收同一文件 → 晋升 → 核验公开附件”流程发布。产品构建输入改变则重建候选与证据。用户可取消、可再次打开设置、可从失败恢复，均是产品门槛。

2h/8h、资源场景对照、物理多屏/DPI、无障碍与公网故障沿用 [.11 遗留清单](plan_0_1_11.md)并说明实际覆盖，不以短测声称长期稳定，也不自动变成本版等待时长。
