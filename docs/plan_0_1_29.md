# 0.1.29 计划：程序图标、资源与签名发布

状态：计划（2026-10-29），待开发。`Cargo.toml` 仍为 0.1.28，未打 tag、未公开。main 上已有图标、资源嵌入与签名预备提交（97b1717）及文档提交（7940dff、3decdca、4d43bd3）。背景见 [plan_port_macos_linux.md](plan_port_macos_linux.md) §0。

## 0a. 定位

Winmgr 是 MiniCon 系列的窗口管理子产品。签名身份与证书配置在系列内共用（公司账户、`minicon-public` 证书配置），每个仓库有自己的 Entra 应用、精确 GitHub 主体与签名者角色。登记与状态索引见公司仓 `skills/sign-windows-artifacts/references/product-signing-log.md`。

## 1. 用户问题与目标

- 问题：程序在资源管理器、任务栏和文件属性里没有图标与公司、版本信息；发布附件未经公司签名，Windows 会显示未知发布者。
- 目标：0.1.29 的 `minicon-winmgr.exe` 与 `minicon-tskmgr.exe` 带图标和版本资源，并由公司 Artifact Signing 签名；签名回执记录在版本清单中，正式发布由签名后的产物晋升。
- 不变：用户功能、配置键、更新协议与哈希校验规则。

## 2. 已完成（main 上，本地可验证）

- [x] 图标：`assets/icon/generate_winmgr_icon.py` 复用 MiniCon 图标生成器的光栅化与 PNG 写入，生成 `assets/winmgr.ico`（16、24、32、48、64、256），可重复生成。
- [x] 资源嵌入：`build.rs` 为两个二进制分别嵌入图标与版本信息（产品名、公司、文件说明、原始文件名、内部名）；manifest 仍走链接参数，没有重复。
- [x] 签名前构建顺序：`build_candidate.py --tool-only` 输出未签名 Tskmgr 摘要；`--signed-tool` 绑定签名后的 Tskmgr 再编译 Winmgr。默认无参数行为不变。
- [x] 签名工作流 `winmgr-signed-candidate.yml`：手动触发，`confirm_provisioned` 未勾选时直接失败，不产生未签名输出。它不是发布路径，`candidate.yml` 与 `release.yml` 未改。
- [x] 签名身份（2026-10-29）：仓库专属 Entra 应用、联合凭据（精确 GitHub 主体）、仅限 `minicon-public` 证书配置的签名者角色、`release-signing` 环境中的三个 secret，以及已有的三个 variable。只读核对：GitHub 侧 READY；Azure 侧 READY，四个签名者各有一个精确主体。

## 4. 验收标准

- 签名：`Get-AuthenticodeSignature` 对两个 exe 返回 Valid，发布者为 PARTNERNET SOFTWARE PTY LTD，RFC 3161 时间戳存在。
- 资源：文件属性显示产品名、公司、文件说明与图标。
- 更新：0.1.28 能通过现有 zip 路径更新到 0.1.29；更新按签名后的 zip 摘要校验，清单与之一致。
- 发布：草稿与签名候选字节一致，公开 release 的 SHA256SUMS 与 exe 摘要匹配。

## 5. 决策（默认值已给，owner 可改）

- **D1 0.1.29 是否以签名版发布。** 默认：是。若 C 未通过，则不以签名名义发布；改为未签名候选发布，`signing.mode` 保持 off，并先报告原因，不冒充签名。
- **D2 是否由 agent 直接触发签名运行。** 默认：需要 owner 明确同意，因为会调用签名服务并产生一次签名交易。
- **D3 发布后是否由 release.yml 直接接受签名 run。** 默认：是，通过清单绑定签名 run，而不是重新构建。
- **D4 国内下载速度。** 本版沿用 GitHub 下载，不处理镜像。
- **D5 移植计划 §7 的待决问题。** 不在本版决定。

## 6. 风险

- 签名后的 exe 哈希与未签名版本不同。所有摘要按签名后产物重算；本地未签名候选的哈希不能作为发布依据。
- `Azure/artifact-signing-action` 的 `files-folder`、`files-folder-filter` 参数第一次真实运行前要核对输出。
- 签名证书有效期很短，必须有 RFC 3161 时间戳。
- 本地 `az` 登录只用于只读核对，发布不依赖本机会话。
- 0.1.26 遗留的真实 150% 显示器检查仍未做，不属于本版必需项。

## 7. 停止条件

- 签名失败即停：任何 Authenticode 不为 Valid、发布者不符、缺少时间戳，都不发布；不得以未签名产物替代。
- 失败只追到受影响的一个节点，不扩大为全套回归。
- 公开发布属于既定目标，但签名运行仍按 D2 执行。
