| 风险 | 直接证据 | 结论 |

| 手动下载工具后仍因缺校验表无法打开 | 按生产方式先构建工具，再以其 SHA-256 构建 Winmgr；两份 exe 放在隔离目录，无 SHA256SUMS、空工具缓存，从实际 My tasks 入口打开同目录工具 | 本地路径通过，无下载确认或缓存生成；工具实际普通令牌、同用户/会话 |
| 错误文件被当作同版工具 | 内置摘要匹配/错误内容拒绝、有效缓存回退及原坏文件保留的组件正反例 | 内容校验未放宽；仅名称相同不足以打开 |
| 旧构建丢失可用性或失败重试失效 | 无内置摘要时的双文件校验表校验；缺表说明、当前主程序不匹配拒绝、下载中断/错误内容/重试及目标冲突组件 | 开发回退和既有失败语义通过 |
| 已有正确文件却再次下载 | 使用已取得校验表的本地文件复用组件：将正确文件安装到缓存并保存校验表；错误文件保留、不写入空缓存 | 本地利用路径通过 |
| 官方双产物未绑定 | 打包测试拒绝缺失/错误的绑定输入，拒绝前不生成附件目录；匹配摘要可生成构建记录；旧格式晋升兼容 | 14 项打包/晋升测试通过 |

## 2. 本地双产物与实际入口

`build_candidate.py` 先生成工具，再以该工具摘要构建主程序，构建后再次检查工具未变化。此次本地生产方式构建的摘要：

- Winmgr：`b5e3161262f44f74d4a782d3c8da4f2850c78fcd8a5ed0757d63cbd6d8e86dc1`
- Tskmgr：`4ebbcf7d0469f586af75930e6c6b4e5cccece905c85daca5e48769399dca7ecd`

`tool_offline_probe.py` 通过实际入口核对新工具的路径、摘要、真实普通令牌和正常退出，Winmgr 在工具关闭后继续运行；结束后原正式外壳及工作区恢复。没有替换用户安装文件，没有修改代理或发起 UAC。原始运行报告保留在忽略目录。

这些是本地构建证据，不冒充准确 CI 候选或已经公开。公开前还需接受正式候选、原样晋升和核对附件、真实 .17 → .18 更新与对应工具获取。
