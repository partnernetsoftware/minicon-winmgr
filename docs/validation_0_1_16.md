## 失败与限制

首次原生探针在正常关闭处失败：完成前一个异步激活动作后按钮仍被禁用，探针提前点击。定向诊断直接记录 `before_close_enabled=false`、`Working…`；等待按钮可用后，实际目标句柄结束、启动器退出 0。后续仅补测关闭及尚未执行的结束/取消与翻译路径，保留失败报告，没有修改产品关闭语义或放宽退出断言。诊断脚本曾等待错误提示词，修正为直接核对进程退出，未作为产品失败或通过计数。

中英和明暗代表截图已目视核对，当前桌面 DPI 下布局可用；物理混合 DPI/多屏和屏幕阅读器未覆盖。复制信息控件可用性及 Unicode 剪贴板实现经核对，尚未实际写入用户现有图像剪贴板；尝试建立独立窗口站的探针在环境准备阶段收到拒绝访问，没有改权限或修改用户剪贴板。源码/组件检查与实际复制不是同一种证据。

当前验证均未触发 UAC、修改登录注册表或用户安装文件。正常外壳仍为用户原先运行的版本，不把候选测试冒充用户已安装升级。

## 新发现的菜单退出故障

补测窗口菜单定位时，合成右键未取得实际前台输入，探针发出的菜单按键没有完成选择；这一探针错误不能证明定位功能失败。随后退出暴露真实故障：日志已有 `WM_CLOSE`/`WM_DESTROY`，但自有测试进程仍持有单实例锁，消息窗口已不存在，原外壳无法重启。保留的转储显示主线程停在 `win32u!NtUserTrackPopupMenuEx`，与用户是否成功选择菜单无关。

只对身份、路径和摘要均核实的自有测试进程取转储并结束，随后恢复原正式 Winmgr；其他会话未动，工作区恢复为原值。原始自动恢复报告保留失败，不改写成成功。`.14` 既有一次退出超时仍未证实同因，不据此关闭旧问题。

新增从不激活的私有桌面回归：打开真实原生菜单，发退出请求，检查菜单是否自然结束；失败时只取消本测试菜单以快速收尾。修复前稳定失败，主线程在退出时调用 [EndMenu](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-endmenu) 后通过，严格 Clippy 通过。候选阶段执行这条优化原生回归，不扩大到历史全桌面测试。

此前 `.16` 草稿及未公开标签已撤回，旧候选即使 CI 绿色也不再晋升。新准确候选、实际菜单定位和公开交付仍待完成。

修复后的首次 CI 在测试程序查找阶段失败，尚未执行原生回归：PowerShell 没有捕获 GUI 子系统测试程序的 `--list` 输出。本地复现后改由 Python 子进程捕获并等待，要求准确匹配唯一测试程序；查找与私有菜单退出回归已共同通过。产品源码未因此改变，不把基础设施失败误称为产品回归失败。
