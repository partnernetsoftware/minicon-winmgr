# 0.1.15 计划草案：旧启动路径与剩余状态边界

> 2026-10-18 收口调整：本页仅作维护候选资料，不默认排期后台化、全面迁移或结构重构。实际出现影响使用/恢复的缺陷时再选取必要改动，项目不为凑齐这些版本继续扩展。

状态：**较远期候选设计，待前版结果复核，尚未实施**。更新：2026-10-17。依据：[审阅 C05/C06/C09](review_0_1_12.md)。承接 [0.1.12](archive/plan_0_1_12.md)、[原性能备选草案](archive/plan_0_1_13_performance_draft.md)；若范围经复核仍过大，应再拆版本，不能因本页已有版本号就一次性实施全部项目。

## 1. 目标

让 Alt+Space/隐藏菜单的扫描、排名及启动路径遵守与 Run 一致的后台责任边界；解决 pin/recents 仍依赖 exe 可写目录和账户共享的问题。对回复/图标总量先做测量，再决定是否需要额外容量约束。

本版不重做应用搜索产品。旧菜单仍默认关闭，不恢复已退役入口。优先保留现有数据和行为，再收敛实现。

## 2. 核心候选切片

15-01 可共享后台扫描和任务预算，但 Run 与旧启动器的历史语义仍独立；不得顺手合并成功命令历史和应用频次。recents 是否仅在启动 API 接受后记录，应在实施前核对使用方并更新相应规格，避免失败启动被当作成功使用。

15-02 开工前先确定旧数据归属。exe 旁共享文件不能证明属于当前账户，不能无提示复制给每个用户；确定适用的确认/迁移方式和只读源退化。Shell 与工作区记录已由前版各自处理，本版不再次迁移它们。

## 3. 容量与结构：先验证再决定改动

审阅只确认 Run 回复通道类型和托盘注册表缺少硬性总数上限，没有证明发生泄漏。先在隔离环境测量生产/消费速率、隐藏 UI、慢消息泵和图标 churn 下的峰值、队列寿命及释放，再确定是否增加合并/容量策略。

若需限制，必须说明达到上限的行为：不能因丢失 Run 启动终态让界面永久 busy，也不能随意删除有效托盘注册却继续向应用报告成功。没有可靠语义方案前，不为追求“全部有界”添加任意数字；确有持续增长时按问题严重性提前修复，不等本版本号。

`taskbar`、`settings_panel` 的文件内职责整理仅随相关改动开展，先分清状态、布局、绘制和外部动作的所有者；不以文件行数为拆分指标，不安排全仓重写或机械包装全部 Win32 调用。

## 4. 验收与范围复核

采用临时用户目录/覆盖路径/故障源测试迁移和慢 I/O；原生键盘与焦点、快捷启动外部编辑、实际应用发现及启动要在准确候选上回归。诊断数据、组件容量实验、完整产品功能和用户反馈分别记录，不将合成峰值当作日常内存承诺。

长期资源与设备/无障碍/公网矩阵继续沿用[现行清单](archive/plan_0_1_11.md)，不把它们虚构成已完成，也不在本页另行复制排期。UWP 分组、电源/IME 实时状态、可浏览桌面、签名和 watchdog 保持未排期。

开工时复核三个核心候选的规模。若迁移与后台化不能在清晰边界内完成，优先交付可独立验证的一组，将其余写入新的后续计划；目前不预造 0.1.16 及之后的空版本承诺。

## 5. 新增维护跟踪（不自动排期）

0.1.14 的真实 UAC 测试中，一轮正常 WM_CLOSE/WM_DESTROY 后进程未在 8 秒内退出，原因尚未定位；已核实身份后仅清理自有测试实例并恢复原运行环境。后续取消授权轮次退出与恢复正常，尚不能据此宣称该问题已修复。详见[验收记录](validation_0_1_14.md)。再次出现时优先保留线程/退出阶段证据并做必要修复，不为此启动上面的存储迁移或后台化草案。
